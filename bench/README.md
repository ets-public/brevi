# Brevi benchmark

Small and big stdin/stdout tasks (`tasks/`), each with tests generated by the reference solutions in `ref/gen.py`.
A model solves each task in one language and checks it with `run.sh LANG TASK FILE`, which logs every attempt to `logs/`.
`python3 analyze.py "logs/round1/*.jsonl"` prints the summary.

Token counts are exact: `tokcount.py` asks Anthropic's count_tokens endpoint (Sonnet tokenizer, `claude-sonnet-5-5`) and caches results by content hash in `tokcache.json`. It needs `BENCH_ANTHROPIC_KEY`. Logs marked `"tok":"exact"` use it; older logs (runs before `e1`) hold estimates from `esttok.py` (words, numbers and symbols), which undercount by 12 to 19%.
Each check also logs `patch_tok`: for a retry, the tokens of the lines changed since the last check (removed plus added, never more than the file), from `patchtok.py`. `analyze.py` prints both `loop_total` (every check counts the whole file) and `patch_total` (retries count as patches). `retro_patch.py RUN...` scores older runs the patch way from their saved attempts.
`python3 recount.py` counts every saved solution and error output both ways and writes `logs/recount.json`.
`run.sh` uses `../target/release/brevi` unless `BREVI` is set (runs before the rename are named `-axon`).
`python3 subject_prompt.py RUN LANG small|big` prints the prompt given to a test-subject model; subjects may only run code through `run.sh`.

## Release test (plain Python, since 1 Nov 2026)

Brevi's release test is the plain-Python trial: the model gets the ordinary Python prompt and tools, writes `.py` files, and Brevi builds and runs them in place of CPython. Plain Python runs the same day as the baseline:

```
python3 e2e.py RUN --lang pyb --model sonnet --set xl3 --jobs 1
python3 e2e.py RUN --lang python --model sonnet --set xl3 --jobs 1
# the same with --model haiku, then a second run
python3 e2e.py --summary "logs/e2e/RUN*.jsonl"
```

The test passes when, averaged over two runs, `pyb` costs no more dollars than `python` for both Sonnet and Haiku, and passes at least as many tasks. A task whose solution is also wrong under CPython is not counted. The weekly Monday benchmark runs this test. Latest result is run `e14` (1 Nov 2026, one run): Sonnet $0.205 against $0.176 (1.16x), Haiku $0.024 against $0.025 (0.94x). Not yet passed. `py_as_brevi.py` tracks the share of saved Python solutions that Brevi builds and runs correctly unchanged.

## GUI programs (set `gui`, since 1 Nov 2026)

Three tkinter apps from `ref/gen_gui.py`: `todo_app` (entry, list, checkbox, dialogs), `calc_app` (grid of buttons, key bindings, history) and `tictactoe_app` (canvas clicks, drawing, `after` countdown). The model writes an ordinary tkinter program. Tests drive it without a screen: `mainloop()` reads actions from stdin (`click Add`, `type 1 milk`, `tap 1 50 50`, `wait 1000`, ...) and `show` prints the window as text. Under CPython that is the stand-in in `tkshim/` (on `PYTHONPATH` for `--lang python`); built by Brevi it will be `runtime/brevi_tk` in headless mode. `tools/gui_shim_check.sh` checks the two print the same. Expected outputs come from the reference programs in `ref/gui/`.

First run `g1` (1 Nov 2026, Python only): Sonnet 3/3, all first try ($0.054); Haiku 3/3, all first try ($0.007). Brevi cannot build tkinter programs yet, so `--lang pyb` fails every task; this set measures that work.

## Huge programs (set `huge`, since 1 Nov 2026)

Programs of 200 to 750 lines over 3 or 4 files, where Brevi's plain-Python acceptance drops off (on 1 Nov, 95% of saved solutions under 40 lines built unchanged, 11% of those over 150 lines). Three held-out tasks from `ref/gen_huge.py`: `minilang` (an interpreter for a small language), `chess` (a referee with castling, en passant, promotion, mate and undo) and `adventure` (a text-adventure engine with world checking). Run like the release test with `--set huge`.

First run `h1` (1 Nov 2026, one run each):

| | Python passes | Python $ | Brevi-built Python passes | Brevi-built $ |
|---|---|---|---|---|
| Sonnet | 3/3 | $0.237 | 2/3 | $0.500 |
| Haiku | 3/3 | $0.034 | 0/3 | $0.057 |

None of the six passing CPython solutions (199 to 727 lines) builds with Brevi unchanged. First blockers: adjacent f-strings joined across lines, a field set to `None` in `__init__` and to a tuple later, parameter types only known from a call in another file, and `type(v) is int` checks on values that hold several types (the interpreter's values).

## End-to-end benchmark (`e2e.py`, 1 Nov 2026)

`run.sh` scores code written plus errors read. `e2e.py` counts everything the Claude API bills for a finished task: the system prompt (the Brevi guide, cached), tool calls and results, thinking, text and retries, read from each response's `usage`, and prices it in dollars. Each task is a fresh conversation with the same tools in both languages (`write_file`, `edit_file`, `check`, plus `guide` for Brevi). `python3 e2e.py RUN --lang brevi --model sonnet --set xl3` runs a set; `python3 e2e.py --summary "logs/e2e/*.jsonl"` prints totals. Task sets live in `subject_prompt_sets.py`.

Held-out XL set 3, effort medium, two runs (e1, e2), 12 tasks per row, every task passed:

| Model | Language | Passed at first check | Output tokens | Guide cache write | USD |
| --- | --- | --- | --- | --- | --- |
| Sonnet | Brevi | 9 | 39,228 | 57,085 | 0.564 |
| Sonnet | Python | 11 | 26,905 | 32,674 | 0.358 |
| Haiku | Brevi | 5 | 129,526 | 134,824 | 0.085 |
| Haiku | Python | 7 | 72,542 | 80,475 | 0.047 |

Brevi costs 58% more than Python with Sonnet and 78% more with Haiku. Most of the gap is output (thinking and text, 46% more with Sonnet, 79% with Haiku) and the guide in the prompt; the finished code is about the same size. This is a larger gap than the code-and-errors benchmark shows.

Third and fourth runs (e3 cold, e4w one task at a time so the guide stays cached) keep each conversation in `work/e2e/.../conversation.json`, with thinking summaries. With a warm cache the guide costs almost nothing (about 4,600 cached tokens read per call). The gap is model output and the cache writes of that output in later turns: Sonnet Brevi $0.315 vs Python $0.187 (e4w). The thinking summaries show why: in Brevi, models stop to work out rules that differ from Python, mostly the scope of top-level names (3 of 8 Sonnet and 5 of 10 Haiku thinking blocks), plus copies vs `mut`, `Result` and whether a parser accepts a form. Python runs show none of this. `--thinking between_tools` turns thinking off on Sonnet for comparison.

`python3 py_as_brevi.py` hands every saved Python solution to `brevi check` unchanged and lists the most common first errors. On 1 Nov 2026, 56 of 580 (9.7%) pass. The top blockers are `;` between statements (126), `import` lines (sys, json, datetime, heapq, csv), `def main()`, raw-string regexes, `|`/`&` on sets, and `.splitlines()`/`.rstrip()`. After the library batches (#32 to #39) and the roadmap thread's syntax work, 271 of 580 (46.7%) pass the fast check and 162 (27.9%) also build (`--full`).

Later runs on the same 6 tasks, warm cache, one at a time (`--jobs 1`):

| Run | Model | Brevi USD | Python USD | Note |
| --- | --- | --- | --- | --- |
| e5 | Sonnet | $0.262 | $0.182 | after #32 to #35; Brevi +44% (was +58%) |
| e5 | Haiku | $0.044 | $0.025 | Brevi +77% |
| e6g | Sonnet | $0.411 | (e5) | `--guide guides/python_first.md` |
| e6g | Haiku | $0.053 | (e5) | `--guide guides/python_first.md` |

The draft Python-first guide (e6g) cost more than the Brevi guide. On the single-file tasks the cost was about the same, but the code was 20 to 50% longer than plain Python: the guide's list of limits made models write cautious, fully annotated Python. Most of the extra cost came from the two multi-file tasks (quiz, warehouse), where models wrote `from stock import Stock` and module-level code in the other files. Brevi does not accept that yet. Other blockers seen: `"-" * 40`, `set.discard`, `None` for a missing date, and `.count`/set comprehensions on strings (the last two fixed in #39). Next: accept Python imports between files, cut the limits list down, then run the A/B again.

After imports between files (#41), type annotations (#44) and a shorter guide, the A/B was run again on the same compiler (two runs each, `e8`/`e9` with BREVI.md, `e8g`/`e9g` with `guides/python_first.md`):

| Model | BREVI.md USD (2 runs) | Python-first USD (2 runs) | Checks, BREVI.md / Python-first |
| --- | --- | --- | --- |
| Sonnet | $0.282, $0.249 | $0.256, $0.262 | 15 / 22 |
| Haiku | $0.044, $0.044 | $0.043, $0.046 | 24 / 46 |

The two guides now cost about the same (Sonnet 2% less with Python-first, Haiku 1% more, and one Haiku task failed). Python-first runs still hit more compile errors: nested `nonlocal`, `a or b` used as a value, return types with bare `list` parameters, methods of a class imported from another file, `today = None` without a type. Each one fixed should move Python-first ahead. Plain Python in Python costs $0.182 (Sonnet) and $0.025 (Haiku) on the same tasks.

The strictest test of "Python in, Rust speed out" is `--lang pyb`: the model gets exactly the Python prompt and tools, writes `.py` files, and `check` builds them with Brevi instead of running CPython (run `e10`, same 6 tasks). None of the 6 programs built at the first check with either model. Sonnet cost $0.421 (5 of 6 passed) against $0.189 in Python; Haiku $0.046 (2 of 6) against $0.026. The blockers were all plain Python the compiler did not accept yet: lists of mixed types, untyped module globals and `x = None`, some annotations (`tuple[int, ...]`, string annotations), docstrings in imported files, `xs[:] = ...`, `not a <= x <= b`, for/else, and library calls (`set.update`, `format(x, spec)`, `datetime.strptime`, `timedelta`, `calendar.monthrange`). The library calls are now supported; the syntax items are with the parser work. Run `e11`, after the library batches (#47, #48, #49) and the parser batch (#46): Sonnet $0.513 (4 of 6 passed, 0 built at the first check), Haiku $0.044 (4 of 6, 1 built at the first check; e10 was 2 of 6). The errors left are almost all type inference on unannotated Python: dicts used as mixed-type records, parameters and return types that cannot be worked out, module-level names used in functions, and `x = None` that later holds a dict. Run `e12`, after #50 to #52 (shared values written back, unlimited ints, more inference): Sonnet $0.396 (5 of 6 passed, 1 built at the first check), Haiku $0.037 (5 of 6, 2 at the first check). Plain Python on the same tasks costs $0.189 and $0.026, so the gap went from 2.2x to 2.1x (Sonnet) and from 1.8x to 1.4x (Haiku) since e10. Run `e13`, after #53 and #55 (class fields, module globals, mixed records, loop write-back): Sonnet $0.275 (6 of 6 passed, 4 built at the first check), Haiku $0.029 (4 of 6, 4 at the first check). That is 1.45x and 1.1x plain Python. Without the quiz task, whose records hold a different type in one tuple slot per question kind, Sonnet costs $0.157 against $0.146 in Python and Haiku $0.017 against $0.020. Run `e14`, after #56 and #57 (values whose type differs per row held as JSON, import aliases), with plain Python rerun the same day for a fair baseline: Sonnet $0.205 (6 of 6 passed) against $0.176 in Python (6 of 6), so 1.16x; Haiku $0.024 (5 of 6) against $0.025 (6 of 6), so 0.94x. Haiku's one failure (quiz) is also wrong when run with CPython. Every first attempt from e11 to e14 except that one now builds and matches Python's output.

## Editing benchmark (`edit/`)

Four change requests to an existing 120-line program (`edit/base/shop.{py,ax,rs}`), the kind of edit a model makes most often.
`edit/run.sh LANG TASK FILE` tests the changed program and logs the tokens in the changed lines only (`difftok.py`), plus errors read.

## Speed benchmark (`perf/`)

Four programs written the plain way in Axon, Python and Rust: word counts (2M words), Dijkstra on a 100k-node graph, a prime sieve to 5M, and grouping 1M records.
`python3 perf/gen.py` makes the inputs; `perf/time.sh` builds everything and prints the best of 3 runs.

`verify.sh OLD_BREVI [NEW_BREVI]` rebuilds every saved solution in `solutions/` with both compilers (in parallel; `JOBS=4`) and prints `OK`, `DIFF` or `BUILD` for each one the old compiler could build.

## Guide size check (31 Oct 2026)

`guide.sh RUN WORD` lets a subject look up guide lines; each lookup is logged as task `_guide` and counts as tokens read. Held-out big tasks (`new`), one or two runs each, patch totals:

| Runs | Guide | Sonnet | Haiku | First try (Sonnet / Haiku) |
| --- | --- | --- | --- | --- |
| c1 | old full guide, 5,035 tokens (`guides/BREVI-v0.18-full.md`) | 4,027 | 4,849 | 5/6 / 6/6 |
| g1, g2 | first trim, 2,889 tokens, data formats moved out | 5,993 | 6,025 | 9/12 / 11/12 |
| h1 | final trim, 3,490 tokens, data formats kept | 4,443 | 4,886 | 4/6 / 5/6 |

The first trim cost more: without the regex and JSON details models wrote longer code and looked up `dec` and dates every run. The final trim reads 1,545 fewer guide tokens per session (not part of the totals above) for a task total within run-to-run noise.
