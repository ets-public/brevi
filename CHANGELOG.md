# Changelog

Each release's section here becomes its GitHub release notes (`.github/workflows/release.yml`; `release-notes.yml` re-syncs the notes of an existing release). Benchmark figures are tokens per finished task (code written plus errors read, retries scored as patches), from [bench/LEADERBOARD.md](bench/LEADERBOARD.md).

## Unreleased

- From the e27/e28 trials (every task passing, 19 of 24 native): a bound method passed as a callback (`orders.fill(sku, stock.take)`, then `take(sku, n)` inside); a parameter named like a module (`def fill(self, sku, stock)`, then `stock.take(...)`) is the parameter, not the module; a loop over `sorted(m.get(k, []), ...)` that changes its items no longer raises KeyError for a missing k; `min(d)` / `max(d)` on a dict give a key; a name set to tuples of different lengths in separate places (`c = (t, a, b)`, later `c = (n, path)`) is a new name each time when each setting is only read after it; `al = run.get(k)` takes the entry's type; `sc = g.scores[name]` then `sc[q] = v` types the field's inner dicts. All 5 e27/e28 fallbacks now build natively and pass every test.
- Python libraries in Python files: `import numpy as np`, `pandas`, `sqlite3`, `subprocess`, `pathlib`, `urllib.parse`, `hashlib` and any other installed module now run inside the native binary, through CPython loaded at run time (libpython). Their values, methods, operators (including `a @ b`), iteration, comprehensions and exceptions (`except sqlite3.OperationalError`) behave exactly as in Python. Brevi's own modules stay native; what they lack (`math.gcd`, `d.strftime(...)` on a date) is taken from CPython, learned from the build's errors. A list passed to a library sees its changes (`random.shuffle(xs)`), and lambdas work as callbacks. Before this, any such import made `brevi run` fall back to python3. 12 of 12 realistic library programs now build and match CPython (they used to fall back), and 25 of 32 short library snippets do. The other 7 are older native gaps, now with the roadmap.

- Dynamic values (a parameter or slot whose type could not be fixed) get the text and list methods Python code uses: slicing, `lower`, `upper`, `strip`, `split`, `startswith`, `endswith`, `replace`, `find`, `isdigit`, `isascii`, `sorted(..., key=)`, `reversed`, `sep.join(xs)` and more (e25/e26 fallbacks). Fixed silent wrong output: `s[i]` on dynamic text gave None (so a time check like `s[2] != ":"` was always true); it now gives the character, and an index past the end of dynamic text or a list raises IndexError.
- From the e24 trial: a function kept under another name at the top level (`_old_end_call = end_tx`, called inside a function defined above it); int arithmetic and comparisons with a value read from a mixed dict (`self.total(n) * 100 // self.max`, checked to be an int when it runs); a dict record whose list key only `setdefault` makes (`cur.setdefault("msgs", []).append(m)`, then `r.get("msgs", [])`). Before, that last one would have printed the messages as missing. Sonnet's books, quiz and poker attempts from e24 now build natively and pass every test.
- Huge set: `_, frm, d, to = c` with c a dynamic tuple gives dynamic values (they were unknown, so a field filled from them was never typed); a dict keyed by tuples with a dynamic slot is read, tested and set with plain keys (`self.exits.get((self.loc, d))`, also through a key kept in a name); a dynamic value appended to a list of str is checked to be a str; a dict keyed by dynamic values is read with a plain key. Haiku's h1 adventure (the saved solution) builds and matches CPython on all 9 tests; 12 of the 18 saved huge solutions now build.
- Fixed wrong output: `Fraction(1, 3) + Fraction(1, 6)` printed 0.499999999 (a Fraction was a 9-place decimal). A Fraction is now exact for every denominator that divides lcm(1..32)*10 (thirds, sevenths, 1/64, 1/1000 ...), prints as `1/2` (`Fraction(1, 2)` inside a list), floors with `//` as Python does, and stops with an error naming the value rather than round one it cannot hold (`1/41`).
- `@lru_cache` / `@cache` (also `functools.`) on a function memoises it, as in Python; before, the decorator was dropped, so a memoised recursion such as `fib(80)` ran in exponential time. Methods and `*args` functions still drop it.
- `json.dumps` of a literal with lists or dicts of mixed values (`json.dumps({'a': [1, 2, {'b': None}], 'c': True}, indent=2)`) builds; it was refused.
- From the e25/e26 trials: a name inside a comprehension no longer takes the type of the same name in a later loop (`[pt(x) for x in tk[3::2]]` next to `for i, (nm, x) in enumerate(st)` made pt's parameter dynamic); a list or dict literal with a None or empty slot (`heap = [(start, 0, (), frm, None)]`, `{(frm, t, None): []}`) takes that slot's type from what is put in later; a name set from a function that returns a dict record (`cur = new()`) gets the keys set on it later (`cur.setdefault("out", []).append(m)`). a dict record kept in a one-slot holder or under a key (`cur = [None]`, `cur[0] = {...}`; `state['cur'] = {'bad': True}` next to the full one) is one record, also through `tx = cur[0]` and `t = state['cur']`; a row pushed as `[name, {}]` is a fixed-slot row (a tuple), and `rows[i][1][q] = v` types its dict. With the dynamic-value methods from #111, all 8 e25/e26 fallbacks (trains, books, quiz, poker) now build natively and pass every test.
- Fixed a refusal added in #103: `b, turn, rights = state` followed by `b = list(b)` and changes to b was refused as a copy that cannot be written back (Sonnet's h2 chess); b is a new list there, so nothing needs writing back.

## v0.20.0 (2 Nov 2026)

Plain Python now always runs: `brevi run x.py` builds a native binary when it can and otherwise runs the file with python3, with a one-line note naming what stopped the build. Python objects, rows and records are shared by reference as in Python, values without one fixed type become dynamic values, error classes are real classes, files can be read and written with `open()`, and tkinter programs build (headless for tests, or a real window with `--window`). The parity probe of short Python programs shows no silent differences from CPython. On the release test, measured the fair way (runs e25 and e26, right after this release with #104 added, each side's prompt cache kept apart; every task passing), plain Python built by Brevi costs 0.99x CPython with Sonnet and 0.98x with Haiku. 16 of 24 final programs built natively (67%; it varies by run, 39 of 48 in e23 and e24; the bar is 90%), so the release test is not passed yet. Earlier runs (e15 to e24) let CPython reuse the prompt cache Brevi's runs had paid to write, which counted against Brevi (those runs showed 1.04x to 1.08x). brevi-lang.org leads with AI agents again: the fast, safe target for AI-written Python.

- Faster builds: the runtime prelude is compiled once per rustc version into a cached library instead of being rebuilt with every program (a build goes from about 0.73 s to 0.36 s, `brevi check` from 0.55 s to 0.21 s), and builds are cached by a hash of the generated code, flags and rustc version, so running the same program again takes about 0.1 s. Programs are built without debug info (5 MB to 1.1 MB). The compatibility check of 1,971 old solutions drops from about 6 to under 3 minutes. `BREVI_NO_CACHE=1` and `BREVI_NO_RTLIB=1` turn these off.
- `brevi mcp` keeps the program between calls: send `code` once, then change it with `patch` (whole functions by name) or the new `edit` (a range of lines), which check again in the same reply, so a retry costs the changed lines instead of the whole file. Multi-file programs work through `file`. `run` takes `cases` (stdin and expected output), builds once, and prints `ok` or the first differing line per case. `show` prints the kept program with line numbers. Calls that pass `code` work as before.
- Sorting by a key (`xs.sort_by(f)`, `sorted(xs, key=f)`) works out each key once, as Python does, instead of twice per comparison. `--release` builds keep the prelude inside the program so its functions can be inlined.
- An end-to-end benchmark, `bench/e2e.py`, counts every token and dollar the API bills per finished task (guide, thinking, tool calls, retries). On held-out XL set 3 Brevi costs 58% more than Python with Sonnet and 78% more with Haiku, mostly in model output; see bench/README.md.
- More of Python's library works unchanged: `rstrip`, `lstrip`, `strip(chars)`, `splitlines`, `isupper`, `islower`, `isalnum`, `heapq` (`heappush`, `heappop`, `heapify`, `heappushpop`, `heapreplace`) on a plain list, `deque` with `popleft`/`appendleft`, `map(f, xs)`, `filter(f, xs)`, `list(xs)`, `map(int, xs)` and `key=len`, `sorted(s)` of a string, and `sys.stdout.write`. The share of saved Python solutions Brevi accepts unchanged (`bench/py_as_brevi.py`) goes from 9.7% to 13.1%.
- Python's `Decimal(x)` and `d.quantize(q, rounding=...)` work; a `dec` now remembers how many places it was written with (`1.50`, or what quantize set), which Python-style printing shows. `csv.reader(sys.stdin)` and `csv.reader(lines)` give the rows, and `date.fromisoformat(s)` is `date(s)`. Values that print in Python's style (`True`, `2.0`, `['a']`, `{'k': 1}`) are ready in the runtime for programs written as Python.
- More Python: `next(rows)`, `xs.pop(i)` and `m.pop(k)` (which give the item back), `sorted(s)`, `enumerate(s, 1)` and `sep.join(s)` on a string, `sorted(m)` on a map, `(d2 - d1).days` on dates, and `OrderedDict()`. In Python mode `int("q")` fails with Python's message.
- `OrderedDict` as an LRU cache: `move_to_end(k)` and `popitem(last=False)` / `popitem()`.
- Python's `re` module: `re.compile`, `re.match`, `re.fullmatch`, `re.search`, `re.findall`, `re.sub`, `re.split`, compiled-pattern methods, and `m.group(n)`/`m.groups()`. `next(it, default)` and `next(x for x in xs if c)`.
- The build cache now includes the runtime's hash and the brevi version, so a changed runtime (after an upgrade) never reuses an old build or error.
- More Python: `zip(xs, ys)` (also with a string), `Counter(xs)` with `c.most_common(n)`, `dict(pairs)`, `sys.exit(n)` and `sys.exit(msg)`, `s.discard(x)`, `s.count(sub)`, `zfill`, `title`, `center`, `capitalize`, and `{c for c in s}` on a string. A comprehension's `if i % 2` uses Python truth. A program with `import` or `from ... import` lines now prints the Python way (`True`, `['a']`, `{'k': 1}`, `4.0`), as programs with `def` or `class` already did.
