# Changelog

Each release's section here becomes its GitHub release notes (`.github/workflows/release.yml`; `release-notes.yml` re-syncs the notes of an existing release). Benchmark figures are tokens per finished task (code written plus errors read, retries scored as patches), from [bench/LEADERBOARD.md](bench/LEADERBOARD.md).

## Unreleased

- Python tkinter programs now build. Brevi compiles the widgets, `StringVar`/`IntVar`/`BooleanVar`/`DoubleVar`, `pack`/`grid`/`place`, `command=` callbacks (function names, lambdas, `lambda ch=ch: ...` in a loop), `bind` with the event (`e.char`, `e.keysym`, `e.x`), `after`/`after_cancel` (also `after(ms, f, x)`), canvas items, listboxes and `messagebox` dialogs onto the `brevi_tk` runtime, which is built into the program (no crate to download). Built programs run headless for now: `mainloop` reads test actions from stdin and prints the window, exactly as the CPython stand-in does. Programs written with top-level functions work (Sonnet's to-do app in the `gui` set passes every test); programs built around a class (`self.on_click` as a callback) wait for Python object sharing. A lambda's default values (`lambda k=k: ...`) also work outside tkinter. Other GUI libraries (`pygame`, `PyQt`, ...) still give a clear "not supported" error.
- GUI benchmark set `gui` (`bench/ref/gen_gui.py`): a to-do app, a calculator and tic-tac-toe in tkinter, tested headlessly. `bench/tkshim` is a headless tkinter stand-in for CPython that prints the window the same way as Brevi's GUI runtime (`tools/gui_shim_check.sh`). Plain Python passes all three first try with Sonnet and Haiku; Brevi cannot build tkinter programs yet.
- String literals written next to each other are joined, as in Python, also across lines inside brackets: `("abc "\n "def")`, `f"{n} " f"items"`.
- New held-out benchmark set `huge` (`bench/ref/gen_huge.py`): an interpreter, a chess referee and a text adventure, 200 to 750 lines over 3 or 4 files. First run `h1`: plain Python passes 3/3 with Sonnet and Haiku; Brevi-built Python 2/3 with Sonnet (2.1x the cost) and 0/3 with Haiku. See [bench/README.md](bench/README.md).
- Python programs split over several `.py` files now build: `import stock` and `from shop.store import Store` find `stock.py` or `shop/store.py` (next to the importing file, then next to the main file, as Python does; folders with `__init__.py` are packages). A module's own `if __name__ == "__main__":` self-test is left out when another file imports it. Importing a GUI library (`tkinter`, `pygame`, `PyQt`, ...) now says plainly that Brevi has no GUI support yet, instead of a confusing type error.
- More plain Python from the e14 trial's first attempts: a lambda called at once (`(lambda s: (s[0], s[1]))(score(t))`); rows of a mixed list changed in a loop (`backorders.append([oid, sku, left])`, then `for b in backorders: b[2] -= got`); dicts built from a method's parameters (`self.lots.append({"seq": n, "sku": sku, "qty": qty})`) and dicts with a key that is a keyword (`'type'`) become records; and a loop that changes the dicts a helper returns after filtering and sorting them (`lots = [l for l in self.lots if ...]`, `lots.sort(key=...)`, `return lots`) changes the stored dicts, as in Python. The e14 Sonnet poker and warehouse and Haiku warehouse first attempts now pass every test, and Haiku's quiz builds and prints what Python prints.
- More plain Python from the e15 trial's first attempts: dicts built from local names and filled in key by key (`cur = {...}` then `cur["k"] = v`) become records, including keys that are keywords; a dict whose keys are set in a loop (`memo[k] = v`) is typed as a dict, not a list; `re.I` / `re.IGNORECASE` flags; `math.floor`/`ceil` on decimals; a lambda's nested tuple unpacking (`for (a, (b, c)) in ...`); and a helper that filters a local copy of a list and returns it writes changes back. Wrong output turned into errors: a loop at the end of a function that changes copies, removing items from a list while looping over its indexes, and a list that may be None or an empty list (`[] if ok else None` then `is None`), which Brevi can't yet tell apart. The e15 Sonnet poker and quiz, Haiku warehouse and Haiku trains first attempts now pass every test. Fixed wrong output: `h, a = teams[home], teams[away]` followed by `h['P'] += 1` now changes the stored dicts (Haiku's y2 league). 409 of 580 saved Python solutions pass `brevi check` unchanged, 342 build, and 341 of those give the right output on every test.

## v0.19.0 (1 Nov 2026)

Brevi now aims to build plain Python unchanged ("Python in, Rust speed out"). The release test is a plain-Python trial: models write ordinary Python, Brevi builds it, and the full API cost is compared with running the same models' Python on CPython. In run e14 Brevi costs 1.16x Python with Sonnet and 0.94x with Haiku, from 2.2x and 1.8x this morning. 331 of 580 saved Python solutions build and give the right output unchanged. The release test is not passed yet.

- From the e14 retries: `{d:+.2f}` keeps the plus sign on a Decimal, Python's `string` constants work (`string.digits`, `from string import ascii_lowercase`, and the same for uppercase, letters, hexdigits and octdigits), and JSON values can be dict keys and set items.
- The release test is now the plain-Python trial (`e2e.py --lang pyb` against `--lang python`, same day, Sonnet and Haiku, two runs). It passes when Brevi-built Python costs no more than CPython and passes as many tasks. See [bench/README.md](bench/README.md#release-test-plain-python-since-1-nov-2026).
- Plain-Python trial `e14` (model writes .py, Brevi builds it): Sonnet 1.16x the cost of plain Python (2.2x in e10 this morning), Haiku 0.94x. See [bench/README.md](bench/README.md).
- Python values whose type differs from row to row now work. This is the quiz pattern: a question's answer key is a letter, a set of letters, a `(value, tolerance)` pair of decimals or a list of words, depending on the question type. Such a value holds JSON, whether it is a slot of the returned tuples (also nested, `return qid, ('multi', pts, frozenset(s))`), a class field given different types by different calls (`Question(qid, kind, pts, data)`), or a name set to different types in the branches of an if (`spec = parts[3]` / `spec = frozenset(s)` / `spec = (Decimal(v), tol)`). Where such a value meets a decimal or a list it is read as one: `abs(v - spec[0]) <= spec[1]`, `s == spec`, `s & spec`, `ans in spec`, `value, tol = q.data`. Also `a <= b` / `a < b` on sets as a subset test, `all(words)` / `any(xs)` on strings and numbers (by truth), `\Z` and `\A` in regexes, fields named `type` (`q.type`), `Decimal(a) / Decimal(b)`, `Fraction(Decimal(s))`, `s.casefold()`, `order, questions = [], {}`, `a, b = s.split("=", 1)` inside a loop, and `best = None` with 5- and 6-tuples. Fixed wrong output: `dq = lots.get(sku, deque())` (or `[]`) followed by changes to dq now changes the stored list, as in Python. Every quiz first attempt from the e11, e12 and e13 trials now builds and prints what Python prints. 404 of 580 saved Python solutions pass `brevi check` unchanged, 334 build, and 331 of those give the right output on every test.

- Python import aliases: `from datetime import date as Date`, `import datetime as dt`, `from collections import Counter as C` (for modules Brevi has built in). `datetime.timedelta(...)` works like `timedelta(...)`, and a date that is still None prints `None` in Python files. Together these fix Haiku's failed books task in e13.
- Clearer build error when rustc can't work out a variable's type: it names the variable and says whether it starts as None or as an empty collection, instead of the general "type annotations needed". This rustc error is no longer shown when a more specific one is also reported. Run `e13` of the plain-Python trial is in [bench/README.md](bench/README.md).
- More Python classes from the e12 trial: `self.lots.setdefault(sku, []).append(lot)` types the field as a dict of lists, `for k in list(self.lots):` goes over the dict's keys, a loop that changes the items a small helper method returns (`for lot in self._ordered(sku):` with `return sorted(self.lots.get(sku, []), key=...)`) changes the stored items, `dealt.update(cards)` types a set from a list, and `st = stats[k]` / `dd = nxt.setdefault(k, {})` followed by `st[0] += q` or `dd[t] = x` types the entry, and a name set on some passes of a loop keeps its value into the next pass (`if key != prev: pos = i + 1` then `print(pos)`; this gave wrong ranks before), and `if best:` works on a tuple that started as `best = None`. The e12 warehouse and trains first attempts (and e11 sonnet trains) now pass every test. 403 of 580 saved Python solutions pass `brevi check` unchanged, 327 build, and 324 of those give the right output on every test.

- Python dicts used as records (`tx = {'n': n, 'date': d, 'posts': [], 'bad': False}`: fixed keys, values of different types) become record types, the way a class does. `tx['posts'].append(p)`, `tx['bad'] = True`, `tx.get('k', d)` and `'k' in tx` work; dicts put in the same name with fewer keys (`cur = {'silent': True}`) join the record; records print as the dict and go into JSON as an object. Also: a class's fields filled from outside the class (`shelf.items.append(x)` on a top-level object), a helper that returns an item of a dict (`st = stat(sku)` with `return stats[sku]`) changes the stored item, and `m = months.setdefault(date[:7], [0, 0])` with a computed key writes back. The books first attempts from the e11 and e12 trials now pass every test. 398 of 580 saved Python solutions pass `brevi check` unchanged, 318 build, and 315 of those give the right output on every test.
- Python loops that change the items of a sorted or copied list (`for lot in sorted(lots, key=...)`, `for b in list(backorders)` that may also `backorders.remove(b)`) change the list's own items, as in Python: the loop goes over indexes and each change is written back. Records written as lists of mixed types (`lots.append([expiry, seq, sku, qty])`) are tuples with settable slots (`lot[3] -= n`), Python's `xs.remove(x)` takes out the first item equal to x, and `c = d.setdefault(row[2], [0, 0])` then `c[0] += n` changes the stored list.
- Python lists that hold values of more than one type (a tokenizer's `tokens.append(int(s[i:j]))` next to `tokens.append(c)`) hold JSON values, and arithmetic, comparisons, `abs`, `//`, unary minus and `in` work on them as in Python; JSON values print as Python prints them (`[1, '+', 2]`, `None`, `True`). Also `f'{"#" * n}'` (a value starting with a quote inside a single-quoted f-string) and `\` at the end of a line to continue it. 309 of 580 saved Python solutions now build unchanged, and 305 of those give the right output on every test.
- Python code can set a name again to a value of another type in the block that made it (`w = int(w)` on a loop name, `st = int(st)` after `ip, st, path = m.groups()`): from there on the name holds the new type, as in Python. Also unpacking a list into up to 12 names (`ip, ts, meth, path, proto, st, size, ref, ua = m.groups()`), and `dist.get(v, INF)` with `INF = float('inf')` on a map of ints. 292 of 580 saved Python solutions now build unchanged (260 before).
- More Python: `frozenset(xs)`, `m.pop(k, default)`, `s - k` on sets made with `set(...)` in a function whose types are only known later, `x = None` for 4-tuples, and dates inside a mixed-type dict.
- Python's unlimited ints: in a Python-style program, a number read with `int(text)` that is only added, subtracted, multiplied, compared and printed becomes a big integer, so `a, b = int(p[0]), int(p[1])` / `print(a + b)` works for 60-digit numbers (all 24 saved `bigadd` Python solutions now give the right output; they hit a runtime error before). Any other use keeps it a fast int. Also `re.split` with groups gives the groups' text too, `x = m.setdefault(k, [0, 0])` shares the stored value as in Python, and Decimals inside lists and dicts print as `Decimal('1.50')`. With the parser work, 247 of 251 built Python solutions now give the right output on every test (`py_as_brevi.py --full --run`).
- A function that returns a JSON value on some paths and a number on others (`if isinstance(x, (int, float)): return x` ... `return 0`) now returns JSON, and `sum(f(v) for v in xs)` over such results works, so the usual recursive JSON-walking code builds unchanged.
- Python code that relies on shared objects no longer gives wrong output silently. `for a in m.values()`, `for k, a in m.items()` and `for i, x in enumerate(xs)` that change the item now change the original. Where a change would still be lost (changing items of `sorted(lots)` in a loop, changing a list after putting it in another, changing an item picked by `max(...)`), `brevi check` refuses the program and says how to write it. Also fixed wrong output from plain Python: `range(a, b, -1)` counted nothing, `if x:` was true for a None number or string, `(x,)` was taken as x, `m.setdefault(k, 0)` alone on a line did nothing, and `/` inside an f-string's `{...}` was whole-number division. `bench/py_as_brevi.py --full --run` now also runs each built solution on its task's tests: 224 of 248 built solutions give the right output on every test (188 of 247 before these fixes); most of the rest need Python's unbounded ints (`int("123456789012345678901234567890")`), which stop with an error rather than a wrong answer.
- More Python from the plain-Python trials: module-level values built by comprehensions or calls (`R = {c: i for i, c in enumerate(s)}`, `dict(pairs)`, `[(c, 1) for c in s]`) can be read inside functions; nested functions that call each other (`expr()` calling `peek()`) pass along what the callee reads from the outer function; `def __len__` is what `len(x)` calls and `def __str__` / `__repr__` is how an object prints; a parameter is typed from calls inside generators (`all(valid(c) for c in hand)`); a loop name that is still unknown no longer hides an earlier setting of the same name; `tuple(xs)` works (kept as a list); and `m.get(k)` on a map of maps or lists gives an empty value when k is missing.
- Python names share objects, and Python-style programs now follow that: `r = rows[k]` or `r = resting.get(rid)` followed by `r[0] -= t`, or `acct = accts[name]` followed by `acct.bal += 5` / `acct.deposit(5)`, changes what the container holds. Before, the change was silently lost, giving wrong output. Brevi-style programs keep their copies. Also nested unpacking (`(a, b), c = ...`, `for bid, (r, d) in m.items()` in comprehensions), Brevi keywords used as Python names (`def var(...)`, `match = ...`, `type = ...`), lists filled by `heapq.heappush` typed inside nested functions and changed there (`heappop` in a nested function changes the outer heap), `x.quantize(...)` typed as a decimal, and printing of 4- and 5-tuples.
- Python code that reads JSON works more often unchanged: `json.loads(s)` and `json.load(sys.stdin)`, `isinstance(v, int)` and `isinstance(v, (str, list))` (on a JSON value it checks what the value holds; on other values it follows the type, with bool counting as int as in Python), `v is None`, `v == 3` and `for x in v` / `sum(f(x) for x in v)` on a JSON value. 355 of 580 saved Python solutions now pass `brevi check --fast` unchanged (334 before). A function that returns a JSON value on some paths and a number on others is not supported yet. Also `x = None` that is later a Decimal (prints `None` until set), and `Fraction` as an annotation.
- More Python from the plain-Python trials: `for ... else:` and `while ... else:`, `lots[:] = [...]` (the caller's list changes), `not 1 <= mo <= 12`, `y, mo, d = (int(x) for x in s.split("-"))`, a docstring at the top of an imported file, quoted and loose annotations (`-> "int | None"`, `-> object`, `c: list = [0] * 3`), `pl = pd = None` with one name set later, tuple constants used as lists (`SIZES = ("S", "M")`, `for s in ("a", "b"):`), `()` as an empty list, lambdas that unpack rows (`key=lambda r: r[1]` on lists of lists), and Python printing for scripts with no `def`. A file defining the same function twice no longer makes `brevi check` hang.
- More Python from the guide trials: `nonlocal x` in a nested function changes the outer function's x; `m.group(3) or ""` and other `a or b` / `a and b` on values that are not bools give a value, as in Python; a parameter a function never reads (`stops: list` passed along) is dropped instead of failing to type; `for k in m:` over a dict reads its keys; and a method of a class from another file, or with a built-in name (`board.add(name, row)`, `stock.take(sku, n)`), is called once the value's class is known, with its changes kept. `p[1]` on pairs from a top-level list filled under `global` works inside functions.
- More Python: `d.to_integral_value()` on a Decimal (half to even), `m.setdefault(k, v)` as a statement with any default, `defaultdict(lambda: 0)` (and other empty defaults), `enumerate(xs, start=1)`, `bool(x)`, and `sys.setrecursionlimit(n)` (accepted; native code needs no limit). 334 of 580 saved Python solutions now pass `brevi check --fast` unchanged (321 before).
- More of Python's library: `s.update(xs)` on a set, `m.update(other)` on a dict and `c.update(xs)` on a Counter; `datetime.date(y, m, d)`, `datetime.strptime(s, "%Y-%m-%d")` (`.date()` gives the date), `timedelta(days=n, weeks=w)` added to a date, `d.isoformat()`, `d.toordinal()`, `d.weekday()` (0 = Monday in Python-style files) and `d.isoweekday()`; `calendar.monthrange(y, m)` and `calendar.isleap(y)`; `format(x, spec)`; `float(d)` on a Decimal; `s.isascii()`; and `Fraction(s)` / `Fraction(a, b)` as exact decimals (printed as decimals, not `3/10`). These were the library calls behind failed builds in the new `e2e.py --lang pyb` trial, where the model writes plain Python files and Brevi builds them.
- More Python: `s.ljust(n)`, `s.rjust(n, c)`, `s.split(sep, n)`, `s.rsplit(sep, n)`, `list(s)`, plus `set(s)` and `s.count(x)` on a string whose type only Rust knows, and `a - b` on sets.
- Python type annotations are accepted wherever Python allows them and used where they help: `self.names: list[str] = []` and `self.best: Optional[Lot] = None` on fields, `best: int` with no value, `list[tuple]` and other part-typed annotations (left to inference), `Decimal`, `Union[...]`, `int | str`, `Callable[...]`, `Iterator[...]`. Models write these all the time when they write Python, and they were the most common error left in the Python-first guide trial. Also `x in ("a", "b")`, `m.get(k)` (None when missing), `sum(xs, start)`, and None printing as `None`.
- Faster Python library calls in native builds: `for row in csv.reader(src)` reads rows one at a time with a faster parser (2M rows: 2.8 s and 514 MB before, 0.47 s and 36 MB now; CPython 0.87 s), `Counter(s.split())` counts without building the word list (9.6M words: 1.3 s to 0.32 s; CPython 1.4 s), and regexes match runs like `\S+` in a loop and `re.match` tries only the start (300k lines: 0.79 s to 0.45 s; CPython 0.37 s). `csv.reader` gives `[]` for a blank line, as Python does.
- More Python: `xs.clear()` and `m.clear()`, `sys.argv`, `sorted(m, key=f)` on a dict, and `date(y, m, d)`.
- Python programs split over several files work unchanged: `import stock` / `from stock import Stock, parse` reads `stock.bv` next to the file (`lib.stock` is `lib/stock.bv`), `stock.parse(x)` and `import stock as s` calls work, and a used file may hold `def`, `class`, decorators, imports and module-level constants. This was the main cost of the multi-file tasks in the Python-first guide trial.
- Generators: `yield x` and `yield from xs` (the function collects what it yields, so `for v in f()`, `list(f())` and `sum(f())` work; an endless generator is not supported). `f"{3.14159:.2f}"` and other format specs on a number written in place, `"-" * 40`, `None` for a date, and `try: return f(s)` / `except ...: return None` at a function's end.
- More Python classes and calls work unchanged: `@dataclass` classes (fields from `name: str` lines, with defaults and `field(default_factory=list)`), inheritance (`class Bird(Animal):` gets Animal's fields and methods, and `super().__init__(...)` runs Animal's), Python type annotations (`list[str]`, `dict[str, int]`, `Optional[T]`, `int | None`, `List`/`Dict` from typing), default and keyword arguments (`def scale(x, k=2)`, `scale(5, k=3)`), `*args`, and a class's own method named like a built-in one (`stock.add(4)` next to `seen.add(3)`). In Python-style programs `/` always gives a float (`7 / 2` is 3.5) and an int mixed with a float becomes a float, as in Python. Also `a, b = line.split()` inside a function, `dict(m)` and `Bird("x").describe()`.
- Python classes work unchanged: `class Account:` with `__init__` and methods becomes a type with the fields `self.x = ...` sets, typed from what is put there; `Account("ann", 10)` and `a.deposit(5)` call them. Error classes (`class BadInput(ValueError):`) may have a body. Also `"""docstrings"""` and other triple-quoted strings, `a ** b`, `0xFF`/`0o17`/`0b101`, `fn` as a name, and `st[-1], st[-2] = st[-2], st[-1]`.
- More plain Python is accepted unchanged: `try`/`except`/`else`/`finally` and `raise` (a failing call or `raise` inside `try` runs the handler, with `as e` giving the message), error classes such as `class BadInput(Exception): pass`, `pass`, nested `def` (lifted out, with the names it reads passed along), `;` between statements (also in `if c: a; b`), import lines anywhere, `def main()` with `if __name__ == "__main__":`, raw strings, `return a, b`, `a = b = 0`, `h, m = s.split(":")` from a list, `print(*xs)`, dict and set comprehensions, `{a, b}` sets with `|` and `&`, `<<`, `>>`, `^`, `|=` and the other compound operators, `x is y`, and comprehensions over a dict's keys. With the library batches (#32, #33, #34), 217 of 580 saved Python solutions pass `brevi check --fast` (9.7% before), and 134 (23.1%) build fully. With the class, import and generator batches below, 282 (48.6%) pass and 166 (28.6%) build.
- Types are optional everywhere. A parameter without a type now also takes the type its own function's uses show (`lots.push(Lot(...))`, `seen[id] = true`, `st[t]`, `p.qty`), and `date(s).days` and `weekday()` are typed. With every annotation removed from the 48 saved held-out XL solutions, 46 still build and pass (31 before). The guide now says so and its examples drop their types.
- A parameter changed in place (`xs.push(x)`, `xs[i] = v`, `p.n += 1`) edits the caller's value without `mut`, as in Python. It stays a copy when the function sets it whole or returns it. Leaving out `mut` used to give silently wrong output.
- `global x` and `nonlocal x` are accepted. A program that uses them follows Python's scope rule exactly; programs without them keep Brevi's rule.
- Python's `f"..."` and `f'...'` strings are accepted (Brevi strings already fill in `{name}`).
- A program's own type named `Result` no longer clashes with Rust's.
- A top-level map filled inside a function (`ts = {}`, then `ts[n] = Team()` in a function) is typed where other functions read it, so `fn key(n: str) = (-ts[n].w, n)` needs no return type. This was the most common first-check error in recent runs.
- `inner = m.get_or(k, {})` is typed by what is done with it, like a fresh `{}`, so nested maps built this way at the top level work inside functions.
- A function ending in `if c: m.remove(k) else: print(...)` gives no value, as in Python.
- Functions are values: `ops = [add, mul]`, pairs such as `("+", add)`, and calls straight from a list, tuple or field (`ops[0](3, 4)`).
- A third held-out set of six XL tasks (`bench/ref/gen_big5.py`, runs z1 and z2). Brevi is still behind Python: Sonnet 9,042 vs 7,990 tokens (13% more), Haiku 12,405 vs 11,394 (9% more), from 19% and 4% on the second set. Brevi passes first time more often with Haiku (10 of 12 vs 9 of 12), but its finished programs are no shorter than Python's at this size; type annotations are about 5% of Brevi's tokens.

- `None` for int, float, str and tuple values: `best = None`, `x is None`, `x is not None`, `return None`.
- Maps of functions: `ops = {"+": add, "-": lambda a, b: a - b}`, then `ops[op](a, b)` or `for k, f in ops.items()`.

- Python 3.15 unpacking in comprehensions (`[*xs for xs in xss]`) reads as a comprehension followed by `flatten()` (#15). Rust 1.99 builds cleanly (#13).
- The core guide is trimmed from 5,035 to 3,490 tokens; rare details move to REFERENCE.md, served by `brevi guide WORD`, and CI fails when BREVI.md goes over 3,600 tokens (#18).
- Install channels prepared for launch, not yet published: Claude Code plugin and marketplace, MCP registry `server.json`, a PyPI wrapper, an npm wrapper (`brevi-lang`) and a dataset export of 49 tasks with 1,893 verified solutions (#20).

Examples for LangChain, the OpenAI Agents SDK, CrewAI and the Vercel AI SDK over `brevi mcp` (`integrations/`), and a Homebrew formula generator (#22).

- Faster builds: the runtime prelude is compiled once per rustc version into a cached library instead of being rebuilt with every program (a build goes from about 0.73 s to 0.36 s, `brevi check` from 0.55 s to 0.21 s), and builds are cached by a hash of the generated code, flags and rustc version, so running the same program again takes about 0.1 s. Programs are built without debug info (5 MB to 1.1 MB). The compatibility check of 1,971 old solutions drops from about 6 to under 3 minutes. `BREVI_NO_CACHE=1` and `BREVI_NO_RTLIB=1` turn these off.
- `brevi mcp` keeps the program between calls: send `code` once, then change it with `patch` (whole functions by name) or the new `edit` (a range of lines), which check again in the same reply, so a retry costs the changed lines instead of the whole file. Multi-file programs work through `file`. `run` takes `cases` (stdin and expected output), builds once, and prints `ok` or the first differing line per case. `show` prints the kept program with line numbers. Calls that pass `code` work as before.
- Sorting by a key (`xs.sort_by(f)`, `sorted(xs, key=f)`) works out each key once, as Python does, instead of twice per comparison. `--release` builds keep the prelude inside the program so its functions can be inlined.
- An end-to-end benchmark, `bench/e2e.py`, counts every token and dollar the API bills per finished task (guide, thinking, tool calls, retries). On held-out XL set 3 Brevi costs 58% more than Python with Sonnet and 78% more with Haiku, mostly in model output; see bench/README.md.
- More of Python's library works unchanged: `rstrip`, `lstrip`, `strip(chars)`, `splitlines`, `isupper`, `islower`, `isalnum`, `heapq` (`heappush`, `heappop`, `heapify`, `heappushpop`, `heapreplace`) on a plain list, `deque` with `popleft`/`appendleft`, `map(f, xs)`, `filter(f, xs)`, `list(xs)`, `map(int, xs)` and `key=len`, `sorted(s)` of a string, and `sys.stdout.write`. The share of saved Python solutions Brevi accepts unchanged (`bench/py_as_brevi.py`) goes from 9.7% to 13.1%.
- Python's `Decimal(x)` and `d.quantize(q, rounding=...)` work; a `dec` now remembers how many places it was written with (`1.50`, or what quantize set), which Python-style printing shows. `csv.reader(sys.stdin)` and `csv.reader(lines)` give the rows, and `date.fromisoformat(s)` is `date(s)`. Values that print in Python's style (`True`, `2.0`, `['a']`, `{'k': 1}`) are ready in the runtime for programs written as Python.
- More Python: `next(rows)`, `xs.pop(i)` and `m.pop(k)` (which give the item back), `sorted(s)`, `enumerate(s, 1)` and `sep.join(s)` on a string, `sorted(m)` on a map, `(d2 - d1).days` on dates, and `OrderedDict()`. In Python mode `int("q")` fails with Python's message.
- `OrderedDict` as an LRU cache: `move_to_end(k)` and `popitem(last=False)` / `popitem()`.
- Python's `re` module: `re.compile`, `re.match`, `re.fullmatch`, `re.search`, `re.findall`, `re.sub`, `re.split`, compiled-pattern methods, and `m.group(n)`/`m.groups()`. `next(it, default)` and `next(x for x in xs if c)`.
- The build cache now includes the runtime's hash and the brevi version, so a changed runtime (after an upgrade) never reuses an old build or error.
- More Python: `zip(xs, ys)` (also with a string), `Counter(xs)` with `c.most_common(n)`, `dict(pairs)`, `sys.exit(n)` and `sys.exit(msg)`, `s.discard(x)`, `s.count(sub)`, `zfill`, `title`, `center`, `capitalize`, and `{c for c in s}` on a string. A comprehension's `if i % 2` uses Python truth. A program with `import` or `from ... import` lines now prints the Python way (`True`, `['a']`, `{'k': 1}`, `4.0`), as programs with `def` or `class` already did.
