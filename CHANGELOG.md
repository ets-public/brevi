# Changelog

Each release's section here becomes its GitHub release notes (`.github/workflows/release.yml`; `release-notes.yml` re-syncs the notes of an existing release). Benchmark figures are tokens per finished task (code written plus errors read, retries scored as patches), from [bench/LEADERBOARD.md](bench/LEADERBOARD.md).

## Unreleased

- **Silent wrong output fixed: `\N{NAME}` in `.py` files.** `print("\N{BULLET} item")` printed the escape as text on the typed path and sent the program to CPython from the dynamic build. Both builds now resolve names (any case, aliases) from a table in the compiler, 400 KB of binary size; a bad name, or a computed `CJK UNIFIED IDEOGRAPH-`/`HANGUL SYLLABLE` one, is refused and left to CPython.
- **Silent wrong output fixed: float `sum()`.** Typed builds added floats one by one, so `sum([0.1] * 10)` printed `0.9999999999999999` and `sum([1e100, 1.0, -1e100])` printed `0.0`. Every typed float sum (lists, generators, JSON numbers, Python library values, `sum(xs, start)`) is now compensated as in CPython 3.12+ and the dynamic build, and `sum([-0.0])` prints `0.0`.
- **Uncaught exceptions in Python files exit 1, as in CPython.** Native typed builds exited 101, Rust's panic status, and `bench/compare/compare.py` hid it by only comparing zero with non-zero; it now compares exact exit codes. `.bv` programs still exit 101 after a runtime error.
- **A `.py` file with Brevi-only syntax or methods is refused, as CPython refuses it.** `if a && b:`, `x => x + 1`, `fn f(x):`, `0..n`, `true`, `fail("x")` and `xs.push(1)` on a list used to build and print an answer; now `check` and `build` report one error with the Python spelling and `brevi run` falls back to CPython, which gives the real error. A class's own `push` still works, and `.bv` files keep every Python spelling.
- **Silent wrong output fixed: print arguments and tuple items changed by a later one.** `print(xs, grow(xs))`, where `grow` changes the list (or a global, or `self`), printed the list from before the change in typed builds, and `r = (q, q.pop())` kept a copy of `q`; both now go to the dynamic build and print what python3 prints. None of the 580 saved solutions moved off the typed path.
- **Silent wrong output fixed: a Python file the guard could not read.** When the dynamic parser could not read a file (or a module it imports) that the typed build accepted, such as one using `except*`, every guard check was skipped, so `print({3, -1, 5})` printed the set sorted. Such a file is no longer built typed: `brevi run` runs it with python3, and `build` and `check` report an error. Files with a bare `allow` line now get the guard's checks too.

## v0.24.6 (4 Nov 2026)

> **Breaking: sandbox.** Under `--sandbox`, and in the MCP tools, which sandbox by default, a program's own `# allow read`, `# allow write` or `# allow native` line no longer grants anything. Only the caller grants capabilities: `--allow read,write,native`, `--allow-py requests,pydantic` (CPython for just those Python libraries), or the MCP tools' `allow` and `allow_py` arguments. A sandboxed program whose allow line asks for more than the caller granted is refused. If your setup relied on an allow line in the file, pass the flag or MCP argument instead. Without `--sandbox` nothing changes: a program with an allow line is still held to it.

A security fix release, out ahead of the weekly Monday release: from v0.24.1 to v0.24.5 code written by an AI (or anyone) could free itself from the sandbox by adding an allow line, for example to reach the network through requests. It also brings dynamic builds that call Python libraries instead of falling back to CPython, and native `argparse`, `textwrap`, bytes, `hashlib`, `base64` and a faster native `random`. Release test over two runs on the release commit: Sonnet 1.03x of Python's cost (95% range 0.97x to 1.09x), Haiku 1.02x (0.97x to 1.08x), every task passed on both sides, no check failed because of Brevi, and 47 of 48 and 48 of 48 final programs native (one Sonnet `toc` program ran in CPython).

- **Dynamic builds call Python libraries instead of falling back to CPython.** A Python file that the typed build could not take and that imported a library Brevi lacks (requests, pydantic, yaml, sqlite3, logging, ...) used to run entirely in python3. Now the dynamic build hands just those imports to CPython, which it loads into the program as the typed build's pybridge does, and the rest of the program stays native. Classes built on a library's classes (`class Post(BaseModel)`) are run by CPython as a whole, and `open()` is CPython's. The path line says what CPython runs: `{"path":"dynamic",...,"py":["pydantic","requests"]}`. Library values behave as they do in CPython: attributes, calls with keyword arguments, items, operators, iteration (lazy, so generators print in order), `with`, formatting, `isinstance`, and exceptions you can catch by the library's class or a builtin base, with their attributes. Functions of the program can be passed as callbacks, and a list or dict a library changes is copied back. A multi-file pipeline modelled on [#175](https://github.com/ets-public/brevi/issues/175) (argparse CLIs, a requests client, pydantic models, JSON files) prints and writes exactly what python3 does. `--sandbox` still refuses these imports unless the caller grants them (see the next entry). `brevi check` and `--native` stay strict.
- **Under `--sandbox` only the caller grants capabilities.** A `# allow read`, `# allow write` or `# allow native` line in the program used to unlock that capability under `--sandbox`, so code written by an AI (or anyone) could free itself, for example to reach the network through requests. Now the sandboxed program's own allow lines grant nothing: one that asks for more than the caller granted is refused with `` `# allow native` grants nothing under --sandbox: only the caller grants native``. The caller grants with `--allow read,write,native`, or `--allow-py requests,pydantic` for CPython on the named Python libraries only (not rust fn, crates, or other libraries); in the MCP tools these are the `allow` and `allow_py` arguments. Either flag implies `--sandbox`. Error hints now name the flag to pass, not a line to add. Without `--sandbox`, a program with an allow line is still held to it. **Breaking:** a sandboxed run that relied on an allow line in the file needs the flag instead.
- **Bytes, `hashlib` and `base64` build natively.** `b"..."` literals were refused by the dynamic build and `hashlib`/`base64` ran in CPython; they now build natively (dynamic build), also under `--sandbox`. Bytes values have `bytes(...)`, `str.encode`/`bytes.decode` (UTF-8, ASCII, Latin-1 with `strict`/`replace`/`ignore`, CPython's error messages), indexing, slicing, iteration, `in`, `+`, `*`, comparisons, hashing and the common methods. `hashlib` has MD5, SHA-1, SHA-224/256/384/512 and `new` (pure Rust, no crates); `base64` has b64, urlsafe and b16 encoding and decoding with CPython 3.13's padding rules and `binascii.Error` messages. Fuzzed against python3: 102 hashes over lengths around the block edges, 900 UTF-8 decodes of random byte soup, every base64 edge case tried. Also: `repr()` of a str in dynamic builds now escapes non-breaking and other separator spaces as CPython does (`'\xa0'`).
- **`argparse` builds natively.** Command-line programs that parse their arguments with argparse (21 of the 27 files in the pipeline of [#175](https://github.com/ets-public/brevi/issues/175)) ran in CPython; they now take the dynamic build, also under `--sandbox`. Brevi builds CPython 3.13's own argparse with the program (tools/mkargparse.py, PSF license), so usage lines, `-h` help, error messages and exit codes are CPython's: 54 runs of three test CLIs (subcommands, groups, choices, `nargs`, `BooleanOptionalAction`, custom types, `parse_known_args`) print exactly what python3 prints. A run takes about 3 ms against 23 ms in CPython. `argparse.FileType` and `fromfile_prefix_chars`, which open files, still run in CPython. Also: `brevi run x.py` gives the program `sys.argv[0] == "x.py"` in dynamic builds, as python3 does; `hasattr(value, "__name__")` and similar dunder data were True for strings, numbers and None (argparse tests it); `raise SystemExit(2)` had no `.code`.
- **`textwrap` builds natively.** `wrap`, `fill`, `shorten`, `dedent`, `indent` and `TextWrapper` (all options but `fix_sentence_endings`) now run in the dynamic build, also under `--sandbox`, breaking lines exactly where CPython does (hyphenated words, em-dashes, long words, `max_lines` and placeholders); 1,000 random texts wrapped at random widths print what python3 prints.
- **`random` builds natively outside the sandbox too.** Brevi's own copy of CPython's generator now has its core (seeding, draws, `getrandbits`, `shuffle`) in native code: a loop of 300,000 `randint` calls and 100 shuffles takes 0.15 s, against 0.62 s with the old copy and 0.42 s through CPython (CPython itself: 0.11 s). So a program using `seed`, `random`, `randint`, `randrange`, `choice`, `choices`, `shuffle`, `sample`, `uniform`, `gauss`, `getrandbits` or `Random` with int seeds now takes the dynamic build instead of calling CPython, and draws the same numbers as CPython for the same seed. Other random functions, or a seed that is not an int literal, still use CPython's random.
- **`brevi check` names what stopped the dynamic build too.** When the typed build could not take a file and the dynamic build refused it as well, check reported only the typed reason (`except KeyError: ... and this file cannot be built over dynamic values`), so fixing that line still left the file unbuilt and the real blocker (`import argparse`, a bytes literal) was shown only by `run --explain`. The message now ends with it, as `(file line N: reason)`, and `brevi run` puts it in its `{"path":"cpython"}` line. The generator hint no longer suggests moving a yield out of a try block when the yield is not in one. Found running check over a 27-file production pipeline, where every file stopped on one shared line in an imported module.

## v0.24.5 (3 Nov 2026)

A fix release for four silent wrong outputs in typed builds, the ones the v0.24.4 release test found in its `trains` and `poker` checks: a list name set to None by a nested function, changes through nested `setdefault`, joining tuples, and comparing JSON values. On the 813-program corpus 565 programs build typed, up from 550. Release test over two runs on the release commit: Sonnet 1.06x of Python's cost (95% range 1.01x to 1.12x), Haiku 1.01x (0.95x to 1.07x), every task passed on both sides, no check failed because of Brevi (5 did in v0.24.4), and 48 of 48 and 47 of 48 final programs native (the one Haiku `cron_next` program ran in CPython).

- **Silent wrong output fixed: comparing JSON values.** In typed builds `j == []` (and `j == {}`) was true for a JSON null, 0, False or `""`, and `False == 0` on a JSON value was false; both now answer as Python does. `v is True` / `v is False` on a JSON value is now an identity test (a JSON 1 equals True but is not True), so template renderers that use it build typed.
- **Silent wrong output fixed: a list name set to None by a nested function.** `players = None` in a nested `def` with `nonlocal players` was not seen by the outer function's `players is None`, so a typed poker program printed an extra empty round and read later hands as duplicates. The outer test now sees it.
- **Silent wrong output fixed: nested `setdefault` changes lost.** `d = labels.setdefault(s, {})`, `lst = d.setdefault(k, [])`, then changing `lst` changed only copies in typed builds, so every trip of a typed trains program printed "no route". The change now reaches `labels`.
- **Fixed: joining tuples.** `(tm,) + lab[k]` gave a list in typed builds (a wrong result, or a TypeError where CPython ran fine); it is now one tuple, also when the right side is held as a JSON value.
- **Crate pins.** The crate test and `examples/checksums.bv` now use `sha2` 0.11 and `base64` 0.23. In sha2 0.11 a digest no longer formats with `{:x}`; the examples build the hex string byte by byte. The docs keep `sha2 "0.10"`, which still works.

Release test over five runs (four on main before #171 and #172, one on the release commit): Sonnet 1.06x of Python's cost (95% range 1.03x to 1.10x), Haiku 1.03x (0.98x to 1.10x), every task passed on both sides, 120 of 120 and 117 of 120 final programs native. The run on the release commit alone gave 1.02x and 1.03x. Five checks along the way (of 2 tasks, `trains` and `poker`) failed under Brevi where CPython passed the same files; the models fixed their code and passed, and those typed-build wrong outputs are being fixed for the next release. The 3 programs that ran in CPython were split into several files, where a module Brevi could not build (a `with` other than `open`, `except IndexError`) sends the whole program to CPython.

- **Typed path round 3.** On the 813-program corpus 550 programs build typed, up from 522, none moved off it, and the CPython shadow check finds no wrong output. `j.get(k)`, `j.get(k, [])` and `j.get(k, {})` on JSON values, `json.load(sys.stdin)`, `any(f(x, seen) for ...)` where `f` changes `seen`, `deps or []`, names set inside a loop (or just before its `break`) and read after it, and `return None` from a function returning JSON now build typed. A `MISSING = object()` sentinel is read as None when every test of it also tests None. A loop over a set builds typed when its passes cannot depend on order (adding to sets, appending to the element's own entry, counting, setting a flag).

Keys only some dicts have are now left out while unset, as in Python, and `k in r` and `r.get(k)` see whether the key is set.

Of the 48 final release-suite programs, haiku_csv_join moved to the typed path and prints what python3 prints on the task's tests.

- **`io.StringIO` builds natively.** An in-memory text file (`write`, `getvalue`, `read`, `readline`, iteration, `seek`, `tell`, `truncate`, `print(..., file=buf)`, `with`), and so `csv.writer(io.StringIO())` and `csv.DictReader(io.StringIO(text))`, now take the dynamic build, also under `--sandbox` without `# allow native`. The rest of `io` (`BytesIO`, `open`) still runs in CPython. Both saved csv_join fallback programs print what python3 prints. Also: under `--sandbox` the `{"path":"dynamic"}` line for such programs named `allow native` though none was needed; it now says which modules the typed build lacks.

Of the 48 final release-suite programs, haiku_sudoku moved to the typed path and prints what python3 prints on the task's tests.
- **`json.JSONDecoder().raw_decode` and `json.decoder.scanstring` build natively.** Tokenizers that read a JSON value or string out of a longer text (`v, end = json.JSONDecoder().raw_decode(s, i)`) ran in CPython; they now take the dynamic build, with CPython's indexes and `JSONDecodeError` messages. These were the last 2 of the 48 final release-suite programs that still needed CPython (both `json_query`); both now print what python3 prints on the task's tests.
- **`enum` builds natively.** `class Color(Enum)` with plain values or `auto()`, aliases, methods, properties and an `__init__` taking tuple values, plus `Color(1)`, `Color['RED']`, iteration, `len`, `in`, `__members__`, `@unique`, and `str`/`int` mixins (`class Level(str, Enum)`), now runs in the dynamic build; it used to run in CPython. `repr`, `str`, f-strings, hashing and errors (`ValueError: 7 is not a valid Color`, `TypeError` on `<`) print what CPython prints. `IntEnum`, `StrEnum` and `Flag` still run in CPython. Also: `vars(SomeClass)` works, and a class's attributes keep the order its body defines them in.
- **Exact fractions on the typed path.** `fractions.Fraction` in a typed build held only denominators that divide lcm(1..32)*10, so every Python file importing fractions went to the dynamic build. A Fraction is now a reduced numerator over a denominator (64 bits each, worked in 128-bit arithmetic), so unit tables, matrix elimination and exact ratios such as 1/86400 build typed and print what CPython prints, including `x.numerator`, `x.denominator`, `Fraction("3/4")`, `//`, `%`, `round`, `abs` and `sum(xs, Fraction(0))`. A value that needs more than 64 bits stops with an error naming the limit rather than rounding.
- **More plain Python stays typed.** On the 813-program corpus (bench/typed_corpus.py: saved solutions and repros), 522 build typed, up from 496 on main (386 of the 580 solutions, up from 371); 37 moved onto the typed path and every one with tests prints what python3 prints, and 11 moved off it on purpose (the silent wrong outputs below). `~x`, `yield [x for ...]`, `(only,) = xs`, `d.setdefault(k, {})[j] = v`, `re.sub(pattern, repl, s)` with `repl` a function of the program, a nested function with default arguments, and calls inside a generator inside another generator (`" ".join(fmt(x) for x in r) for r in m`) now build typed. A re group that took no part in the match is None, as in CPython, so `m.group(2) is None` stays typed.
- **Silent wrong output fixed: re groups and tuples.** In typed builds `print(m.group(2))` for a group that did not match printed an empty line instead of `None`, and `print(m.groups())` showed `['a', '', 'c']` instead of `('a', None, 'c')`. A list filled with `tuple(cur)` by a helper function (`out.append(tuple(cur))` on a list passed in, or returned) printed its items as lists. All now match CPython (printing `m.groups()` and such lists goes to the dynamic build).
- **Silent wrong output fixed: rows changed in a loop.** `for r in t[2]: r[1] = v` on rows held in a tuple (a table kept as `(cols, order, rows)`) changed copies of the rows in typed builds, so the update was lost; it now changes the rows themselves, and a loop that changes each row while also reading the rows' owner (`if test(t, r): r[i] = v`) builds over dynamic values. A program whose mixed lists (`[1, 'a']`) have the same item types as one of its real tuples printed those lists as tuples and copied them where Python shares them; it now builds over dynamic values too. Regex patterns also read `\x00`, `\u00e9`, `\f`, `\v` and `\a` escapes, which the typed build matched as letters.
- **Path text from `os` and `pathlib` builds natively everywhere.** A program whose only uses of `os` and `pathlib` are path text (`os.path.join`, `basename`, `dirname`, `splitext`, `normpath`, `os.sep`, `pathlib.PurePath`) used Brevi's own copies of those functions only under `--sandbox`; outside it the program ran in CPython. It now builds natively in both. A program that also reaches files, processes or the environment (`os.environ`, `os.listdir`, `pathlib.Path`, `os.path.exists`) still runs those in CPython, as before.

## v0.24.3 (3 Nov 2026)

`brevi check` gives its verdict in well under a second, and checking or running an unchanged program again replays the cached result in about 10 ms: the median check of a new file went from 559 ms to 144 ms (60 of 65 programs under a second, up from 40), and a re-check from 60 ms to 8 ms median. Standard-library calls now run natively instead of in CPython (of 47 probe programs, 19 needed CPython before and 5 now), `math` and `time` are on the fast typed path (a `math.sqrt`/`math.log` loop over 20 million numbers takes 0.09 s, CPython 1.9 s), and two silent wrong outputs are fixed (`re.findall` with groups, reading a missing defaultdict key). No new release-test run; the v0.24.2 figures stand.

- **Faster `check`, and repeated calls are near-instant.** Agents call `brevi check` and `brevi run` over and over, so every call's wait counts. Three changes, measured on 65 programs (the release suite's saved repros and saved solutions; table in the pull request): (1) `check` and `run` made all eight versions of the generated program up front, each a whole parse and type-inference pass, even when the first one built or was cached; now the others are made only when the ones before fail. (2) A new result cache: `check`, `build` and `run` of files that did not change replay the last result (the same output, `{"path":...}` line and binary) without parsing, inference or rustc, keyed on a hash of the program's files, the command and flags, the `BREVI_*` and Python settings, the Brevi binary and the toolchain. A re-check of an unchanged file went from 344 ms on average (up to 3.9 s) to 11 ms, a re-run from 379 ms (up to 4.7 s) to 18 ms. A refusal is replayed only for programs that import nothing an install could change. The MCP server gets this with no change. (3) `check` of a file on the dynamic path runs rustc's checks instead of a full build (2.8 s to 0.5 s on one program). Type inference also copies its name tables less. `--no-cache` (or `BREVI_NO_CACHE=1`) builds from scratch, `BREVI_CACHE_MB` caps the cache (default 1024 MB, least recently used out first; it was 400 entries), and `BREVI_TIME=1` prints how long each build stage took. Also fixed: a build into a folder that did not exist left its error in the build cache, so building again after creating the folder still failed.
- **Standard-library calls run natively, not in CPython.** A Python file that the typed build could only finish by handing some standard-library calls to CPython (`math.gcd`, `itertools.product`, `statistics.mean`, `copy.deepcopy`, `datetime.datetime.strptime`, `functools.reduce`, `time.perf_counter`) now takes the dynamic build, which has those modules natively: no libpython at run time, and it works under `--sandbox`. Libraries Brevi lacks (numpy, sqlite3) still run in CPython as before. Of 47 small standard-library probe programs, 19 needed CPython before and 5 now (argparse, textwrap, io, os and random; random and textwrap come next); in the 765-program corpus 11 programs moved from CPython to native, and every moved program with tests prints what python3 prints. Also fixed: one missing call such as `math.gcd` sent every `math.` call on its line to CPython, `math.sqrt` included.
- **Silent wrong output fixed: `re.findall` with groups.** With two or more groups `re.findall` returns tuples (`[('a', '1'), ('b', '2')]`), but the typed build gave whole matches (`['a1', 'b2']`). Such calls now build over dynamic values; with no group or one group they stay typed.
- **Silent wrong output fixed: reading a missing defaultdict key.** In Python `d[k]` on a defaultdict puts the key in, so `len(d)`, loops and printing see it; the typed build left the dict unchanged. A program that reads a defaultdict with a key that may be missing and also looks at its keys now builds over dynamic values (a key taken from a loop over the dict's keys, or from `min`/`max` of them, counts as found, so counting and grouping programs stay typed: 1 of the 765 corpus programs moved).
- **`math` and `time` on the fast typed path.** `math.gcd`, `lcm`, `comb`, `perm`, `factorial` (big results grow past 64 bits as in Python), `isclose`, `log` (with or without a base), `log2`, `log10`, `log1p`, `exp`, `expm1`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`, the hyperbolic functions, `hypot`, `fabs`, `trunc`, `degrees`, `radians`, `copysign`, `fmod`, `isnan`, `isinf`, `isfinite`, the constants `pi`, `e`, `tau`, `inf` and `nan`, and `time.time`, `perf_counter` and `monotonic` now build typed, whether imported with `import math` or `from math import gcd, pi`. Domain errors are a `ValueError` an `except` catches, as in CPython, and `math.sqrt(-1)` raises instead of giving nan. A loop of `math.sqrt` and `math.log` over 20 million numbers runs in 0.09 s (CPython: 1.9 s). Of the 47 probes, `math` and `time` programs moved from the dynamic build to the typed one; no program in the corpus left the typed path.
- **Docs:** a [What runs native](https://brevi-lang.org/docs/compatibility#what-runs-native) table lists, module by module, which functions the typed build has, which run in the dynamic build, and which still need CPython.

## v0.24.2 (3 Nov 2026)

Every build off the fast typed path now says which path it took and which function to rewrite, in one JSON line an agent can act on. More plain Python stays on the typed path: of 765 agent-written programs, 477 build typed, up from 429. `random` and path functions work in the sandbox, Python files can use `# allow read` as a comment, fallback errors are shorter (`--traceback` for the whole one), and printing `tuple(xs)` no longer shows a list. Release test on this build (one run): 1.09x Python's cost for Sonnet and 1.06x for Haiku, every task passed, 23 of 24 final programs native for each model.

- **Every build says which path it took.** For a Python file, `brevi run`, `build` and `check` print one JSON line on stderr whenever the file is off the typed fast path: `{"path":"dynamic","line":3,"fn":"show","why":"print() of a set shows CPython's hash order, ..."}`, `{"path":"pybridge","why":"numpy run in CPython","py":["numpy"]}` or `{"path":"cpython","line":2,"fn":"g","why":"Brevi could not build it: unknown function eval()","by":"python3"}`. `line`, `fn` (and `file` in a module) name the code to rewrite to get the typed path back. The typed path stays silent; `--explain` prints it too and adds the fix, up to five more reasons and why the dynamic build refused a CPython run; `BREVI_PATH=1` prints the line for every build, `BREVI_PATH=0` never. The CPython fallback's `note: ran with python3; ...` line is replaced by its `{"path":"cpython"}` line. bench/e2e.py logs each pyb task's final path and adds a `typ` column (tasks on the typed path).
- **More plain Python stays on the typed fast path.** On a corpus of 765 agent-written programs (the saved benchmark solutions and past fallback repros), 429 built typed before and 477 now (372 of the 580 solutions, up from 326), none moved off the typed path, and every moved program with tests prints what python3 prints on them. Loops, comprehensions and prints of a set of strings (or of tuples led by one) build typed: CPython draws string hashes afresh each run, so no order is CPython's own (rustc checks the element type; sets of numbers still go to the dynamic build, which follows CPython's order). A comprehension over a set handed straight to `max`, `min`, `sorted`, `any`, `all`, `len` or `set` no longer counts as an order-dependent use. A sentinel `MISSING = object()` used only to mark "no value" (`d.get(k, MISSING)`, `if old is MISSING:`) is read as None when the program cannot tell the two apart (no other None value reaches it, no truth test on it). Also typed now: `[[int(x) for x in row] for row in rows]` and other comprehensions inside comprehensions that can fail, `d.get(k, {})` and `d.get(k, [])` on JSON objects, `t[:2]` and `t[1:]` on tuples, a lambda set inside a loop or if body, and `datetime.date(...)` in a function with a local named `date`.
- **Silent wrong output fixed: `print(tuple(xs))`.** A tuple made with `tuple(...)` from a list or iterator is held as a list by the typed build, so printing it (or a list of them) showed `[1, 2]` instead of `(1, 2)`. Such programs now build over dynamic values.
- **random, path text and `# allow` work in the sandbox.** Under `--sandbox` and in the MCP tools (sandboxed by default), `import random; random.seed(1)` gave two confusing errors (`unknown method .seed()` and `unknown name 'random'`). random now runs natively there from Brevi's own copy of CPython's generator, so a seeded program draws the same numbers as CPython (`seed`, `random`, `randint`, `randrange`, `choice`, `choices`, `shuffle`, `sample`, `uniform`, `gauss`, `getrandbits`, `Random`); any other random function gives one error naming it and saying it needs `allow native`. Path text no longer needs `allow native` either: `os.path.join`, `basename`, `dirname`, `split`, `splitext`, `normpath`, `isabs`, `os.sep` and `pathlib.PurePath` (POSIX rules) run without CPython, while every call that reaches files, processes or the environment (`os.listdir`, `os.environ`, `os.system`, `pathlib.Path`, `os.path.exists`, `os` passed as a value) is still refused, now by name. New tests in tests/sandbox show each of those stays blocked, and that Brevi's own PurePath has no file access at all. In Python files the allow line can be a comment, `# allow read`, so the file stays valid Python (the bare `allow read` still works and stays the form for `.bv` files), and fixes suggest the comment form.
- **Shorter fallback output.** When `brevi run` falls back to CPython on a sure mistake, it printed the note and then CPython's whole traceback, so the error was read twice. It now prints the note and only the traceback's last line, with where it was raised (`NameError: name 'totl' is not defined (main.py line 3)`). `--traceback` or `BREVI_TRACEBACK=1` shows the whole traceback; other fallbacks are unchanged.

- A top-level map filled inside a function (`ts = {}`, then `ts[n] = Team()` in a function) is typed where other functions read it, so `fn key(n: str) = (-ts[n].w, n)` needs no return type. This was the most common first-check error in recent runs.
- `inner = m.get_or(k, {})` is typed by what is done with it, like a fresh `{}`, so nested maps built this way at the top level work inside functions.
- A function ending in `if c: m.remove(k) else: print(...)` gives no value, as in Python.
- Functions are values: `ops = [add, mul]`, pairs such as `("+", add)`, and calls straight from a list, tuple or field (`ops[0](3, 4)`).
- A third held-out set of six XL tasks (`bench/ref/gen_big5.py`, runs z1 and z2). Brevi is still behind Python: Sonnet 9,042 vs 7,990 tokens (13% more), Haiku 12,405 vs 11,394 (9% more), from 19% and 4% on the second set. Brevi passes first time more often with Haiku (10 of 12 vs 9 of 12), but its finished programs are no shorter than Python's at this size; type annotations are about 5% of Brevi's tokens.
- `s.index_of(sub)` and `s.index(sub)` on strings (-1 when missing).
- `None` for int, float, str and tuple values: `best = None`, `x is None`, `x is not None`, `return None`.
- Maps of functions: `ops = {"+": add, "-": lambda a, b: a - b}`, then `ops[op](a, b)` or `for k, f in ops.items()`.
- More Python habits: `set(xs)` and `s.add(x)`, `xs.extend(ys)`, `xs[::-1]`, `divmod`, `round(x)`/`round(x, n)`, `enumerate(xs, 1)`, `m.setdefault(k, [])`, `defaultdict(int)`, `"%d %s" % (a, b)`, `"{:>5}".format(x)`, `math.sqrt`, `sys.stdin`, `[0] * n`, `p.0.1`, and `import sys`/`from collections import ...` lines. These came from compile errors in earlier benchmark runs.
- Python 3.15 unpacking in comprehensions (`[*xs for xs in xss]`) reads as a comprehension followed by `flatten()` (#15). Rust 1.99 builds cleanly (#13).
- The core guide is trimmed from 5,035 to 3,490 tokens; rare details move to REFERENCE.md, served by `brevi guide WORD`, and CI fails when BREVI.md goes over 3,600 tokens (#18).
- Install channels prepared for launch, not yet published: Claude Code plugin and marketplace, MCP registry `server.json`, a PyPI wrapper, an npm wrapper (`brevi-lang`) and a dataset export of 49 tasks with 1,893 verified solutions (#20).
- Grammar for constrained decoding: `grammar/brevi.lark` and a llama.cpp copy, `grammar/brevi.gbnf`, which accept every test program and all 1,370 verified Brevi solutions. Examples for LangChain, the OpenAI Agents SDK, CrewAI and the Vercel AI SDK over `brevi mcp` (`integrations/`), and a Homebrew formula generator (#22).
- Safe to run: `allow read, write` (or `native`) at the top of a program declares what it touches, `brevi run --sandbox` refuses anything undeclared, and the MCP tools sandbox by default (`sandbox: false` turns it off).
- A second held-out set of six XL tasks (`bench/ref/gen_big4.py`). On it Brevi is behind Python: Sonnet 10,997 vs 9,222 tokens, Haiku 11,851 vs 11,426 (#19).
- Faster builds: the runtime prelude is compiled once per rustc version into a cached library instead of being rebuilt with every program (a build goes from about 0.73 s to 0.36 s, `brevi check` from 0.55 s to 0.21 s), and builds are cached by a hash of the generated code, flags and rustc version, so running the same program again takes about 0.1 s. Programs are built without debug info (5 MB to 1.1 MB). The compatibility check of 1,971 old solutions drops from about 6 to under 3 minutes. `BREVI_NO_CACHE=1` and `BREVI_NO_RTLIB=1` turn these off.
- `brevi mcp` keeps the program between calls: send `code` once, then change it with `patch` (whole functions by name) or the new `edit` (a range of lines), which check again in the same reply, so a retry costs the changed lines instead of the whole file. Multi-file programs work through `file`. `run` takes `cases` (stdin and expected output), builds once, and prints `ok` or the first differing line per case. `show` prints the kept program with line numbers. Calls that pass `code` work as before.
- Sorting by a key (`xs.sort_by(f)`, `sorted(xs, key=f)`) works out each key once, as Python does, instead of twice per comparison. `--release` builds keep the prelude inside the program so its functions can be inlined.
- An end-to-end benchmark, `bench/e2e.py`, counts every token and dollar the API bills per finished task (guide, thinking, tool calls, retries). On held-out XL set 3 Brevi costs 58% more than Python with Sonnet and 78% more with Haiku, mostly in model output; see bench/README.md.
- More of Python's library works unchanged: `rstrip`, `lstrip`, `strip(chars)`, `splitlines`, `isupper`, `islower`, `isalnum`, `heapq` (`heappush`, `heappop`, `heapify`, `heappushpop`, `heapreplace`) on a plain list, `deque` with `popleft`/`appendleft`, `map(f, xs)`, `filter(f, xs)`, `list(xs)`, `map(int, xs)` and `key=len`, `sorted(s)` of a string, and `sys.stdout.write`. The share of saved Python solutions Brevi accepts unchanged (`bench/py_as_brevi.py`) goes from 9.7% to 13.1%.
- Python's `Decimal(x)` and `d.quantize(q, rounding=...)` work; a `dec` now remembers how many places it was written with (`1.50`, or what quantize set), which Python-style printing shows. `csv.reader(sys.stdin)` and `csv.reader(lines)` give the rows, and `date.fromisoformat(s)` is `date(s)`. Values that print in Python's style (`True`, `2.0`, `['a']`, `{'k': 1}`) are ready in the runtime for programs written as Python.
- More Python: `next(rows)`, `xs.pop(i)` and `m.pop(k)` (which give the item back), `sorted(s)`, `enumerate(s, 1)` and `sep.join(s)` on a string, `sorted(m)` on a map, `(d2 - d1).days` on dates, and `OrderedDict()`. In Python mode `int("q")` fails with Python's message.
- `OrderedDict` as an LRU cache: `move_to_end(k)` and `popitem(last=False)` / `popitem()`.
- Python's `re` module: `re.compile`, `re.match`, `re.fullmatch`, `re.search`, `re.findall`, `re.sub`, `re.split`, compiled-pattern methods, and `m.group(n)`/`m.groups()`. `next(it, default)` and `next(x for x in xs if c)`.
- The build cache now includes the runtime's hash and the brevi version, so a changed runtime (after an upgrade) never reuses an old build or error.
- More Python: `zip(xs, ys)` (also with a string), `Counter(xs)` with `c.most_common(n)`, `dict(pairs)`, `sys.exit(n)` and `sys.exit(msg)`, `s.discard(x)`, `s.count(sub)`, `zfill`, `title`, `center`, `capitalize`, and `{c for c in s}` on a string. A comprehension's `if i % 2` uses Python truth. A program with `import` or `from ... import` lines now prints the Python way (`True`, `['a']`, `{'k': 1}`, `4.0`), as programs with `def` or `class` already did.
