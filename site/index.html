The verified native runtime for agent-written Python

Your agent writes Python. Brevi runs it native, checked against CPython.

Brevi compiles the plain Python your agent writes into a native binary, and brevi run --verify checks each run against CPython 3.13. Your harness gets a certified native answer, CPython's own answer, or an answer marked unchecked, never an unchecked one passed off as checked, and every refusal is one line of JSON the model can act on.

$uvx --python 3.13 brevi run --verify main.py

One command with uv: brevi, CPython 3.13 and the pinned Rust, nothing else to install on Linux x86-64 and macOS. Linux ARM64 and Windows too from v0.28.3 (v0.28.2 and earlier need Rust from rustup). Other ways to install.

One loop: write, check, verify, run

The model has no new syntax to learn and no guide to load. Brevi replaces python3 in the agent's loop, and adds a check CPython alone cannot give: that the fast answer is the right one. Run the whole loop yourself.

  1. The agent writes Python

    Ordinary Python 3, with the standard library or installed packages, in one file or many. No type annotations needed.

  2. Brevi compiles it

    It infers the type of every value and writes Rust; where a type changes at run time, Rust over dynamic values instead. A sure mistake comes back before anything runs, as one JSON line with the line number and a fix.

  3. --verify checks it against CPython

    Each run is compared with CPython 3.13 on the same input. Same answer: a certificate the harness can log. Different: CPython's answer, and a {"verify":"differs"} line. Cannot be compared (clock, files, network): a {"verify":"refused"} line, never a silent pass.

  4. Native, or through MCP

    The checked program runs as a native binary, or through brevi mcp, where run checks by default: under its default sandbox, a program on the typed build is checked against Brevi's dynamic build, and any other run says it was not checked. Outside the sandbox, a file Brevi cannot build runs in CPython, and one line says which line stopped the build.

Speed and safety without asking the model for Rust

Models write Python most reliably, but CPython is slow and finds many mistakes only when the broken line runs. Rust is fast and safe, but it takes a model longer and costs more tokens to write. With Brevi the model writes Python and the program runs as Rust.

CPython's own tests

At v0.28.2, of 1,072 tests from CPython 3.13's own suite (ten files, among them test_set and test_patma), 1,043 build natively and print exactly what CPython prints, the rest are refused with a reason, and none answer differently or crash. Of 2,053 of CPython's tests for the standard-library modules agents use most, 1,989 match and none answer differently (tests that run a string as code are left out by design). At v0.27.0 it was 250 of 311 core tests with 8 answering differently, and 250 of 554 stdlib tests with 22. The numbers

No regressions on agent programs

All 591 saved programs from our own benchmark runs still build and match CPython byte for byte, with the same exit status. They passed once and are kept so nothing breaks again: a regression check, not a measure of how much Python works.

{"line":N,"msg":…,"fix":…}

One-line errors

Build and run-time errors are one line that names the source line, a fraction of a traceback's tokens. The agent fixes that line and runs again.

allow read, write

Only the caller grants access

Under brevi run --sandbox and in the MCP tools, a program cannot read or write files, call native code or load libraries unless the caller allows it. allow lines in the source grant nothing. The sandbox is a policy layer, not an isolation boundary: there is no container or VM around the program, and --allow-py and --allow native are full trust. Run untrusted code in a container or VM. No external security audit yet: we have not had an external audit; we are seeking funding for one. Until then, do not run hostile code under the sandbox. Security

numpy · requests · pydantic

Installed packages work

numpy, requests, pydantic, the LLM SDKs, MCP servers, sqlite3 and other common libraries build with Brevi's own native copies; other installed packages, such as pandas, run in CPython inside the native program. tkinter apps build too, and can be tested without a screen.

Rust stable · beta · nightly

Tested against new toolchains

CI builds daily on Rust stable and the newest and next Python, and weekly on Rust beta and nightly. Every benchmark program that once passed must keep passing.

One line per error

An agent pays for every token it reads. A Brevi error names the line, says what went wrong and, where it can, suggests a fix.

brevi check reports certain mistakes before the program runs, with a fix: a name that is never defined, a method no type has, text added to a number. Mistakes Python only finds at run time (an index out of range) fail there, as in CPython. In Brevi's own .bv language every type mistake is caught before it runs. How errors work
