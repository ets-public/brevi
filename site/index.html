A programming language for AI models to write.

Why Brevi

Built for the model in the loop, not for a person at a keyboard.

Every language in common use was designed for people. People type slowly, read error messages once, and remember the libraries they know. A model works differently. It pays for every token it writes, it rereads every error message in full, and each failed attempt costs another round of both. Brevi is designed around that cost.

What a finished task really costs

  1. The code it writes. Fewer lines and fewer tokens for the same program. Brevi has no semicolons, braces, lifetimes or import lines, and the common tasks (CSV, JSON, dates, money, regular expressions) need no setup code.
  2. The errors it reads. An error message goes back into the model's context and is paid for in full. Brevi's errors are one short line. In the examples below they are 42% to 86% shorter than the same mistake reported by Python or Rust.
  3. The retries it needs. Each failed attempt adds another edit and another error. Brevi accepts the Python habits models fall back on, fixes small typos itself, and points to the exact line to change, so fewer attempts fail and each fix is small.

The benchmark counts all three together, with exact token counts. On that measure models finish tasks with up to 21% fewer tokens in Brevi than in Python. On the hard tasks, writing the same programs in Rust, the language Brevi compiles to, takes about 2.4 times as many tokens as Brevi.

The same task in both languages

A sales report from a CSV file: skip bad rows, total revenue by region and month with exact cents, and find the top product. This is one of the held-out tasks, written after the language was tuned. Both programs below are Claude Haiku's own passing solutions, unedited.

sales_report.pyPython · 66 lines · 812 tokens
import csv
import re
import sys
from collections import defaultdict

DATE_RE = re.compile(r"[0-9]{4}-[0-9]{2}-[0-9]{2}")
QTY_RE = re.compile(r"[0-9]+")
PRICE_RE = re.compile(r"[0-9]+(\.[0-9]{1,2})?")


def to_cents(price):
    if "." in price:
        whole, frac = price.split(".")
        frac = (frac + "00")[:2]
    else:
        whole, frac = price, "00"
    return int(whole) * 100 + int(frac)


def fmt(cents):
    return "%d.%02d" % (cents // 100, cents % 100)


def main():
    reader = csv.reader(sys.stdin)
    rows = 0
    skipped = 0
    region_rev = defaultdict(int)
    product_qty = defaultdict(int)
    month_rev = defaultdict(int)
    first = True
    for row in reader:
        if first:
            first = False
            continue
        if not row or (len(row) == 1 and row[0].strip() == ""):
            continue
        if len(row) != 5:
            skipped += 1
            continue
        date, region, product, qty, price = row
        if not DATE_RE.fullmatch(date) or not QTY_RE.fullmatch(qty) or not PRICE_RE.fullmatch(price):
            skipped += 1
            continue
        q = int(qty)
        revenue = q * to_cents(price)
        rows += 1
        region_rev[region] += revenue
        product_qty[product] += q
        month_rev[date[:7]] += revenue

    out = ["rows %d" % rows, "skipped %d" % skipped]
    if rows > 0:
        out.append("regions")
        for region, rev in sorted(region_rev.items(), key=lambda kv: (-kv[1], kv[0])):
            out.append("  %s %s" % (region, fmt(rev)))
        best = min(product_qty.items(), key=lambda kv: (-kv[1], kv[0]))
        out.append("top_product %s %d" % (best[0], best[1]))
        out.append("months")
        for month in sorted(month_rev):
            out.append("  %s %s" % (month, fmt(month_rev[month])))
    sys.stdout.write("\n".join(out) + "\n")


if __name__ == "__main__":
    main()
  • Exact money is built in. row[4].dec() is an exact decimal, so the Brevi program adds up prices directly. The Python program writes its own to_cents and fmt helpers to avoid floating-point errors in the totals.
  • No setup code. CSV parsing and regular expressions are part of the language, so there are no imports, no compiled patterns and no main() wrapper.
  • Missing map keys read as zero. region_tot[row[1]] += rev just works, with no defaultdict or .get(k, 0).
  • And it runs as native code. The Brevi version compiles to a Rust binary, with the speed that comes with it.

Errors a model can act on

No file paths, columns or pages of notes. Each error is one JSON line with the Brevi line number and a suggested fix. Small typos of known names are fixed during the build.

2.90 s → 0.47 s

Rust speed and safety underneath

Brevi compiles to Rust and builds a native binary. The model never writes lifetimes, borrows or semicolons; ownership is worked out by the compiler.

True · .append() · range()

Python habits are accepted

Models write Python by reflex, so Brevi accepts the common spellings instead of rejecting them. Indented blocks, comprehensions, len(), sorted() and ", ".join(xs) all work.

Programs that work the first time

On the 18 small tasks, Claude Sonnet's Brevi programs passed on the first attempt every time, against 35 of 36 in Python. A first-try pass means no error to read and no retry to pay for.

Rust 1.99 · Python 3.15

Keeps working as Rust and Python move

Brevi is rebuilt every day on Rust stable and the newest and next Python, and every week on Rust beta and nightly. Each time, every benchmark program that ever passed is run again. A break is fixed before it reaches a release, so programs written today keep building as the toolchains update.

crates · Python packages

Not limited to the standard library

A program can split over several files, call any Rust crate from crates.io, and run Python code with any installed package. The model writes a short Brevi signature and the library does the rest.

Errors

One line per mistake, with the fix.

Brevi runs its own checks before Rust sees the code, in about 3 ms. Anything Rust still rejects is mapped back to the Brevi line and rewritten in Brevi's own type names, so the model never reads generated Rust.

For agents

Ready for coding agents from the first call.

The compiler ships with the pieces an agent needs to write, check and fix Brevi without a human setting anything up.

  • MCP server

    brevi mcp serves guide, check, run, test and patch over stdio. Each tool takes the program as text, so the agent needs no files.

  • Agent skill

    An Agent Skills package with setup and the write, check, fix loop: skill.md.

  • llms.txt

    Machine-readable entry points at /llms.txt and /llms-full.txt, with the guide as plain Markdown at /guide.md.

  • Edit by name

    brevi patch f.bv p.bv replaces each function, type or test by name, so a fix costs only the lines that changed.

  • Libraries

    use "util.bv" splits a program over files, and use sha2 "0.10" with rust fn or py fn calls Rust crates and Python code: libraries.md.

  • Fast checks

    brevi check f.bv --fast runs Brevi's own checks in about 3 ms without invoking rustc.
