Python in, Rust speed out

The model has no new syntax to learn and no guide to load. Brevi replaces python3 in the agent's loop.

  1. The agent writes Python

    Ordinary Python 3, with the standard library or installed packages, in one file or many. No type annotations needed.

  2. Brevi compiles it

    It infers the type of every value and writes Rust. Where a type changes at run time, it writes Rust over dynamic values instead. rustc makes the binary.

  3. Checked against CPython

    Where Brevi knows it cannot match CPython, it refuses at build time, and brevi run runs the file with python3 instead and says so in one line (--native turns that off). It does not catch every difference yet, so check programs that matter with brevi verify.

Speed and safety without asking the model for Rust

Models write Python most reliably, but CPython is slow and finds many mistakes only when the broken line runs. Rust is fast and safe, but it takes a model longer and costs more tokens to write. With Brevi the model writes Python and the program runs as Rust.

CPython's own tests

Of 311 tests from CPython 3.13's own suite, 181 build natively and print exactly what CPython prints, 66 are refused with a reason, 44 still build and answer differently, and 5 crash. Those 49 are bugs, and they are what we fix first. On main, for the next release, 250 match, 38 are refused, 8 answer differently and none crash. The numbers

591 of 591

No regressions on agent programs

All 591 saved programs from our own benchmark runs still build and match CPython byte for byte, with the same exit status. They passed once and are kept so nothing breaks again: a regression check, not a measure of how much Python works.

{"line":N,"msg":…,"fix":…}

One-line errors

Build and run-time errors are one line that names the source line, a fraction of a traceback's tokens. The agent fixes that line and runs again.

allow read, write

Only the caller grants access

Under brevi run --sandbox and in the MCP tools, a program cannot read or write files, call native code or load libraries unless the caller allows it. allow lines in the source grant nothing. It is a limit layer, not a security boundary: no seccomp or VM, --allow-py is full trust, and no outside review yet. Run untrusted code in a container too.

numpy · requests · pydantic

Installed packages work

numpy, requests, pydantic, the LLM SDKs, MCP servers, sqlite3 and other common libraries build with Brevi's own native copies; other installed packages, such as pandas, run in CPython inside the native program. tkinter apps build too, and can be tested without a screen.

Rust stable · beta · nightly

Tested against new toolchains

CI builds daily on Rust stable and the newest and next Python, and weekly on Rust beta and nightly. Every benchmark program that once passed must keep passing.

One line per error

An agent pays for every token it reads. A Brevi error names the line, says what went wrong and, where it can, suggests a fix.

brevi check reports certain mistakes before the program runs, with a fix: a name that is never defined, a method no type has, text added to a number. Mistakes Python only finds at run time (an index out of range) fail there, as in CPython. In Brevi's own .bv language every type mistake is caught before it runs. How errors work
