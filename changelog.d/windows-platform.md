- **Python libraries on Windows.** A Windows program that imports a library Brevi does not build itself (PyYAML, pandas, ...) now builds natively and runs those calls in CPython through the bridge, as on Linux and macOS, instead of handing the whole file to `python3`. Both typed and dynamic builds use it; the bridge loads `pythonNN.dll` (found from the `python` on PATH, or `BREVI_PYTHON`), and `brevi verify` certifies its output on Windows. `--standalone` is still Linux only.
- **Windows text output uses CPython's CRLF.** A native run on Windows now writes `\r\n` for every text newline, as CPython's text streams do; before, it wrote `\n`, so `brevi verify` reported every program with a newline as differing on Windows.
- **Generators and async on Windows.** Dynamic builds on Windows now run generator and async stacks on Win32 fibers instead of refusing them, so `yield` and `async def` build, run and verify natively there (no CPython fallback).
- **Windows resource limits (cpu, mem).** `brevi run --limit cpu=N,mem=MB` now works on Windows: `brevi` checks the process's CPU time and pagefile usage every few milliseconds and stops it with the usual `{"e":"limit",...}` line and exit 124.
