- **Native engine libraries are pinned by SHA-256.** DuckDB's and ONNX Runtime's libraries (and, on Windows, Python's OpenSSL DLLs) are hashed when a program is built, and the program loads one only if its bytes still match, checked on the very bytes that get loaded (a sealed memory file on Linux, a private read-only copy on macOS, files and folders locked against change on Windows). A library swapped after the build never runs; after upgrading duckdb or onnxruntime, `brevi run` rebuilds by itself and a binary from `brevi build` must be built again.
- **No planted DLLs on Windows.** Every DLL Brevi or a program loads (CPython's, DuckDB's, ONNX Runtime's, OpenSSL's, a `BREVI_*_LIB` override) is loaded by an absolute path with its dependencies searched only in its own folder and System32, never the program's folder, the working folder or `PATH`.
