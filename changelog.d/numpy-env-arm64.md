- Fixed: a built numpy binary ignored the environment it ran in. numpy and its OpenBLAS read `NPY_*` settings, `OPENBLAS_CORETYPE` and the thread counts (`OPENBLAS_NUM_THREADS`, `GOTO_NUM_THREADS`, `OMP_NUM_THREADS`) when they load, and these can change numpy's last digits. A binary now reads them when it starts: under an `NPY_*` or `NUMPY_*` setting it stops before running anything, and under an `OPENBLAS_CORETYPE` naming other kernels or any other `OPENBLAS_*`, `GOTO_*` or `OMP_*` variable it raises `NotImplementedError` at its first float matrix product or linear algebra call. Builds under those OpenBLAS variables use CPython's numpy for such programs, and the result cache keys on them.
- Fixed: on ARM64 (and anywhere Brevi does not model numpy's OpenBLAS kernels), a Brevi-syntax (`.bv`) program using numpy's `@` built natively and then stopped with `NotImplementedError` at the product. It now keeps CPython's numpy, as `.py` files already did.
