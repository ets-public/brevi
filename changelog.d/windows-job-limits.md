- **Windows: `--limit cpu` and `--limit mem`, held by the OS.** On Windows the program now starts suspended, goes into a Job Object with a user-mode CPU-time limit and a committed-memory limit, and only then runs, so it is held from its first instruction; processes it starts are in the same job and count too, and anything left in the job is killed when the run ends. At the limit it stops with the usual `{"e":"limit",...}` line and exit 124, under `brevi run`, `brevi verify` and the MCP server's `run`. Windows has no kernel-time job limit, so `cpu` there counts user-mode time only. `file` and `fds` are still refused on Windows: it has no OS limit for them.
