- Release notes now open with the conformance numbers in full, for both the core and stdlib slices: matches, wrong answers, tests refused by design (they run a string as code and are left out of the count), the share of matches that print something to compare, the matches that print nothing, and the matches that took the typed build. The notes quote every figure or none: `tools/release_notes.py` stops if a report lacks one. When the notes of an existing release are rewritten (release-notes.yml), the numbers come from the reports the tag holds, not from main's, and the release's "Tested" line is kept.
- The conformance reports' percentages are rounded once, from the counts: they rounded the share to four places and then to one decimal, so core assertion-bearing coverage, 945 of 1072 (88.153%), read 88.1% instead of 88.2%. The release gate now compares the counts with the gate too, rather than the four-place rounded share.
