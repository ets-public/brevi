- Dynamic builds take PEP 695 type parameters in full outside class bodies: `def f[T]`, `class C[T]` and `type X[T] = ...` with bounds, constraints, defaults, `*Ts` and `**P`, each evaluated lazily in its own annotation scope as CPython does; `typing.NoDefault`, and `isinstance(x, TypeVar)` (and `TypeVarTuple`, `ParamSpec`) on a PEP 695 parameter.
- A program with a class on `Generic` or `Protocol` (or `class C[T]`) is now refused, rather than answered without them, when it reads a class's `__bases__`, `__mro__`, `mro()`, `__orig_bases__` or `__dict__`, or calls `dir()` or `vars()`: the dynamic build leaves `Generic` and `Protocol` out of a class's bases.
