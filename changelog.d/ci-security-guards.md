- **CI guards against leaked credentials and workflow takeovers.** `tools/secret_scan.py` fails CI when a tracked file holds a credential (Anthropic, OpenAI-style and DeepSeek, GitHub, AWS, Google, Slack and Replicate shapes, private keys) and, run locally, also when one holds the exact value of any of the machine's secret variables, so session logs and transcripts can be checked before they are committed or shared. `tools/workflow_guard.py` fails CI when a workflow uses an action that is not pinned to a commit SHA, gives secrets to a `pull_request` run, uses `pull_request_target`, `workflow_run` or `issue_comment`, runs on `issues` without an author check, or expands outside text into a shell script. Every action is now pinned to a SHA (Dependabot keeps them current), the release workflow passes its tag through `env:`. The auto-fix workflow is removed: it handed issue text built from upstream release notes to a Claude agent holding the Anthropic key and a write token, and printed its transcript into the public job log. Toolchain and upstream issues are still opened, for a maintainer to pick up; auto-fix can come back with a sandboxed design.
