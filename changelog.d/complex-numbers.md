- **`complex` in the dynamic build**: complex literals (`1j`, `3.25-4j`) and `complex()` were refused at build time and now run natively, computed as CPython 3.13 computes them: `complex()` from numbers, strings (`complex('(1+2j)')`), `__complex__`, `__float__` and `__index__`, with CPython's errors; `+ - * / **` with ints, floats and complexes (Smith's division, the small-integer power path, `ZeroDivisionError`/`OverflowError` where CPython raises them); `abs`, `hash` (equal to the int or float hash when the imaginary part is 0), `==`, `repr`/`str`, `.real`, `.imag`, `.conjugate()`, `format()` with every complex format spec, `%`-formatting errors, `pow(z, n, m)` raising "complex modulo", and a negative float to a fractional power (`(-8) ** 0.5`) now giving a complex instead of being refused. Complex values cross to and from libraries CPython runs. The typed build still refuses complex and hands the program to the dynamic build; a subclass of `complex` is refused at build time.
- Dynamic build fixes found on the way: the `z` format option (negative zero coercion) was ignored, so `format(-0.0, 'z.1f')` printed `-0.0`; it now prints `0.0`, and `z` on an int or str raises CPython's ValueError. `iter(it)` of an iterator class of the program's returns `it` itself (`iter(it) is it`), and an `__iter__` returning a non-iterator raises CPython's TypeError. `type(iter(bytearray()))` and `type(iter(memoryview(b)))` are `bytearray_iterator` and `memory_iterator` instead of a refusal. `itertools.repeat(x, times=n)` takes its keyword arguments as CPython does instead of crashing. `range()` with a start, stop or step past 64 bits (`range(sys.maxsize - 5, sys.maxsize + 5)`) was refused and now runs: len, indexing, `in`, `index`, `count`, `reversed`, ==, repr and attributes all match CPython, `len()` of a range too long for an ssize_t raises its OverflowError, and slicing such a range is refused. `hash(range(...))` now follows CPython's rule (length, start, step) and equals CPython's value, so `hash(range(0)) == hash(range(5, 5))`. Iterating a range near the 64-bit limits no longer overflows: `range(sys.maxsize - 2, sys.maxsize, 5)` never ended and `reversed(range(-sys.maxsize - 1, -sys.maxsize + 2))` was empty; both now give CPython's items.
