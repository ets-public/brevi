- CI: pull requests no longer raise the conformance floors or rewrite the published conformance reports (`bench/conformance/`). After each merge, main runs both slices on the merged tree and commits the floors it measures and the reports (`tools/conformance.py --check --raise-floor` in `conformance-main.yml`). `tools/floor_guard.py` fails a PR that raises one, and `--write-baseline` now only lowers them. Every conformance PR used to raise the same two numbers, so each merge put every other open PR into conflict. Each PR then had to merge main, re-measure and re-run CI (#483 ran 9 times).
- The conformance known-wrong lists are now folders with one file per entry (`compat/conformance_known_wrong/`, `compat/conformance_stdlib_known_wrong/`; each file is named `test-id.mode` and holds `issue=#N owner=LOGIN expires=YYYY-MM-DD`). PRs that add or remove different entries no longer conflict, as they did when neighbouring lines of one list changed.
