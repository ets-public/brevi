- **`brevi mcp` no longer lets the model widen its own access.** Over MCP the model writes the calls, so a plain `brevi mcp` now keeps every program sandboxed: a call with `sandbox: false` is refused, and a call can grant only what the person who started the server allowed with `brevi mcp --allow ... --allow-py ... --allow-net ... --allow-read DIR --allow-write DIR` (nothing by default). `brevi mcp --trust-calls` keeps the old behaviour for a client trusted as yourself; the `verify` tool needs it. `--http` passes these flags on. The Python and Node SDKs start `brevi mcp --trust-calls`, since their calls are the host program's, so they work as before. (Found by the 10 November review.)
- **Sandboxed runs are checked by default, without CPython.** The MCP `run` tool under the sandbox, and `brevi run --verify --sandbox` on the command line, now compare the typed build's answer with Brevi's dynamic build, built under the same grants and run under the same limits. When they differ, the answer is the dynamic build's, with a `{"verify":"differs","against":"dynamic",...}` line. This catches all nine critical typed-build repros from the review (lists shared or sorted in a function, `int(1e20)`, `round(x, -2)`, ...). Programs that read the clock, write files or use the network, or that take another build, are not compared and say so. Before, the sandboxed default returned the typed answer unchecked.
- **`--limit written` holds to the byte.** It was read from `/proc` between writes, so one large write could pass it (2 GB got through a 1 MB limit). It is now counted by Brevi's own file layer before each write, on every OS, and like `files` and `net` it needs `--sandbox` without `--allow native` or `--allow-py` (refused otherwise). It counts bytes written to files; stdout and stderr stay `output`, the network `net`. Under it SQLite, DuckDB and ONNX Runtime write no files of their own (their bytes could not be counted): database files open read-only and temporary data stays in memory. `files` and `net` are now passed to the program on Windows too.
- **A sandboxed program starts without the caller's environment.** Under `--sandbox` the program gets only the search path, locale, time zone, terminal size, temp folders and Brevi's own settings (with `--allow-py` or `--allow native` also the home folder and proxy and certificate settings), so keys and tokens in the caller's environment are not in `/proc/self/environ`, even with a read grant.
- **MCP argument checks.** Each `allow_read` / `allow_write` item is one folder or file (an item with a comma is refused, no longer split in two); `code`, `patch` and `text` must be strings (a number is no longer taken as program text); and after a wrong answer with `sandbox: false`, only that same code runs with CPython for the rest of the session, not every later program with the same file name.
- **`--limit threads` is refused.** It was the kernel's thread count read every few milliseconds, so a program could start many threads between two reads; a limit that does not hold is refused rather than kept.
