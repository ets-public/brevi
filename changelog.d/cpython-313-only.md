- **Fixed: Brevi uses only CPython 3.13.** Brevi answers as CPython 3.13 does, but a program that bridges to a Python library loaded whatever `python3` was on PATH, so with a 3.14 or 3.15 there some library calls answered as that version does (bare `pickle.dumps` wrote protocol 5). Now every CPython Brevi asks or runs (the bridge's libpython, the build's questions about modules and packages, the fallback, `brevi verify`, brevi-python and `py` functions) is a CPython 3.13: `$BREVI_PYTHON` when set, else the first 3.13 among `python3`, `python3.13` and `python` on PATH, the `py` launcher (Windows) or `uv python find 3.13`. Any other version is refused with an error that says how to install 3.13, never used. A built program checks the libpython it loads too, and refuses one that is not 3.13.
