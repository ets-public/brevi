- Dynamic builds: assigning or deleting an attribute of a C function (`len.x = 1`, `math.sqrt.y = 2`, `del print.__doc__`) raises CPython's AttributeError instead of storing it; `__module__` stays assignable, as in CPython.
- Dynamic builds: a def of Brevi's own copy of a stdlib module (random, textwrap, os.path, logging, argparse, string, contextlib, asyncio and the rest) has CPython's `__module__`, `__name__`, `__qualname__` and `__doc__` when CPython's is a plain Python function (`textwrap.dedent.__doc__` was None). One that is a C function or method in CPython (`random.random`), one CPython lacks, and the defs of third-party libraries' copies: their type, repr and attributes stop the program instead of answering differently. So do numpy's functions and `exit`/`quit`, whose CPython objects Brevi does not model.
- Dynamic builds: a program's `import _brevi_mt` (or any of Brevi's own `_brevi_*` modules) no longer reaches Brevi's internals: it does not build (CPython has no such module).
