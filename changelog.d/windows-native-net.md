- **Windows: native requests and httpx.** Brevi's own requests and httpx now use Winsock on Windows instead of sending the program to CPython, as they do on Linux and macOS: a non-blocking connect, `select` for the connecting socket and `WSAPoll` for readiness, `ioctlsocket`/`closesocket`, with the same sandbox host checks, timeouts and CPython-style errors (`[WinError 10061] No connection could be made because the target machine actively refused it`). TLS loads OpenSSL with `LoadLibraryA`/`GetProcAddress` from absolute paths only: `BREVI_SSL_LIB` / `BREVI_SSL_DIR`, or the Python DLL folder embedded at build time (no program-folder, CWD, PATH or bare-name candidate). OpenSSL on Windows has no path to the Windows certificate store, so verification also loads a CA bundle: `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE` or `CURL_CA_BUNDLE`, else certifi's bundle embedded at build time. A local HTTP and HTTPS server, the whole `tests/http` requests and httpx suites, and `https://example.com` build, run and verify natively on Windows x64.
