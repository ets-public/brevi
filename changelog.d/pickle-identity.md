- Dynamic build: `pickle.dumps` writes a repeated str, bytes, tuple or complex once and then refers to it, exactly as CPython does, at every protocol (before, `[s, s]` wrote `s` twice: different bytes). Object identity of these values now follows CPython 3.13: equal constants of a module are one object (with CPython's constant folding: `"a" + "b"`, `(1, 2) * 2`, `1 + 1` inside a tuple), and operations CPython answers with the same object (`s[:]`, `s + ""`, `"".join([s])`, `f"{s}"`, `format(s)`, `"%s" % s`, `s.split(sep)` with no match, the bytes equivalents, `t + ()`, `copy.deepcopy` of an atomic tuple) keep it, so `is` gives CPython's answer there too. A tuple of constants whose folding Brevi does not compute (`(2 ** 0.5, 1)`) is refused at build time in a program that pickles.
- Dynamic build: a `collections.defaultdict` or `Counter` crosses into a library as CPython's own type, so `pickle.dumps` gives CPython's bytes and `pickle.loads` gives back a defaultdict with its `default_factory` (before, it pickled as a plain dict and loaded as one: a KeyError on a missing key).
