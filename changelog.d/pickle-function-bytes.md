- Dynamic build: `pickle.dumps` of a function or class the program defines (a def, a class, a method, a nested class, or one from a module of the program) now gives CPython's exact bytes at every protocol: a global (`__main__` and the qualified name, STACK_GLOBAL from protocol 4, `getattr` for a dotted name below it), the module name memoized once and the same object memoized when it comes again. Before, it was saved through a private `_brevi_dyn` helper, which printed different bytes, a silent wrong answer. A builtin class such as `int` or `list` now crosses into a library as CPython's own class, so `pickle.dumps(int)` is `builtins.int` too, and it comes back as the program's class. Loading a pickle that names a missing attribute of a module of the program raises CPython's AttributeError, naming the module with its path.
- Dynamic build: `pickle.dumps`, `pickle.dump` and `pickle.Pickler` default to CPython 3.13's protocol 4 (and `pickle.DEFAULT_PROTOCOL` is 4) even when the CPython on PATH is 3.14 or newer, whose default is 5.
