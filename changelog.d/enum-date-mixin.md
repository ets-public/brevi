- Dynamic builds: an Enum may take `datetime.date` as its data type (`class Holiday(date, Enum)`, `Enum('E', ..., type=date)`); any other instance of a date subclass, and date arithmetic or `replace()` on such a member, is refused. Enum also gains `_add_alias_` and `_add_value_alias_`, CPython 3.13's checks on inheritance order and on extending an enum with members, `_missing_` errors chained to the ValueError, iteration over a class while its members are made, and members whose name a base's property or DynamicClassAttribute uses. `vars()` with no argument is refused at build time.
- Dynamic builds follow enum.py 3.13's class-body rules: a member name bound twice, or bound over a method or property, raises TypeError; `_ignore_` names leave the class; a `functools.partial` in the body warns FutureWarning and is not a member. Namedtuple values are unpacked into `__new__`, a dataclass data type gives members its field repr, and a data type's own `__repr__`/`__str__`/`__format__` gives way to the Enum's. Fixed for every class: `hasattr()` on a builtin value only finds the dunders CPython's type has (`hasattr(frozenset(), '__delete__')` was True), `super().__new__` in an int subclass reaches `int.__new__`, and a body's `__qualname__ = ...` names the class. Refused at build time: a metaclass built on `type(SomeEnum)`, and `X.__new__(...)` in an Enum method other than `__new__`; `type()` of an Enum class is refused at run time.
