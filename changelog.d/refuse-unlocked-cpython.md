- Security: under `--sandbox`, a program that runs CPython (`--allow-py` or `--allow native`) is now refused where the kernel cannot lock CPython to the grants, instead of running it unlocked. That is macOS and Windows at build time (no file lock, and no network lock without `--allow net`), and at start a Linux kernel without Landlock, or Linux other than x86-64 and arm64 without a network grant. Before, with no folders named, CPython there kept full file access, and it kept the network on macOS and Windows. The new `--allow-unlocked-python` flag (also `brevi mcp --allow-unlocked-python` for a server's calls) builds such a program anyway, and it then prints a `brevi: warning:` line naming the missing lock every time it starts. On Linux with the locks nothing changes. Real locks for macOS and Windows are on the roadmap.
