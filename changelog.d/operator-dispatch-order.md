- **Operators on objects run their dunders in CPython's order** in the dynamic build. For `a + b` (and every binary operator), the right operand's reflected method runs first when its class is a strict subclass of the left operand's class and gives that method a different value (its own or an inherited one), and it is not called a second time after `NotImplemented`; two operands of one class never try the reflected method. For `==`, `!=`, `<`, `<=`, `>`, `>=`, a strict subclass on the right is asked first, each method runs once, and when every method answers `NotImplemented` the result is CPython's default (identity for `==`/`!=`, `TypeError` for ordering). `!=` without `__ne__` inverts `__eq__` per side, as `object.__ne__` does, and a `__ne__` returning `NotImplemented` is no longer taken as true. Before, these gave wrong answers or ran a user method twice.
