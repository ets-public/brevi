- **Windows conformance gates a release.** The core CPython conformance slice now has its own Windows floor (`compat/conformance_windows_floor.json`) and known-wrong list (`compat/conformance_windows_known_wrong/`, one file per entry). A release runs `tools/conformance.py --check --release-gate` on the `brevi.exe` it ships, so a Windows wrong result or a Windows score below the floor or 90% publishes nothing. The weekly Windows job now runs the same ratchet and raises the floor on main. The stdlib slice has no Windows floor yet, so on Windows it only measures and refuses to gate. Four `test_set.TestBasicOpsTriple` tests are now classed unstable on every platform: CPython prints a set holding `operator.add`, which it orders by memory address, and Windows CPython prints another order than Linux CPython.
