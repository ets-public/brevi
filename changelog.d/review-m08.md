- **NaN values in containers keep CPython's identity rules.** `x in xs`, list/tuple/dict/set `==`, `.index`, `.count`, `.remove` and dict/set lookups now compare with `is` before `==`, as CPython does, so `n = float('nan'); n in [n]` is True while `float('nan') in [float('nan')]` is False, and computed NaNs are new objects (a fresh identity per `nan + 1`, `inf - inf`, ...). The typed build stops with "NaN identity" and re-runs on the dynamic build only when a NaN is actually compared; programs without NaN keep their speed.
