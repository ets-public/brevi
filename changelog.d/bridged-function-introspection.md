- Dynamic builds: a Python library CPython runs inside the program now sees the program's defs, lambdas and bound methods as CPython's functions and methods: `__name__`, `__qualname__`, `__doc__`, `__module__`, `__defaults__`, `__kwdefaults__`, `__annotations__`, assigned attributes, `co_flags`, `inspect.isfunction`/`ismethod`/`isgeneratorfunction`, binding when put in a class, equality and hashing, `functools.wraps`. They used to arrive as an anonymous builtin, so `inspect.getdoc` printed `None` and a library read the name `brevi_function`. What compiled code cannot answer truly (its bytecode and the other `co_*` fields, `__globals__`, `__closure__`) is refused with `NotImplementedError` when it is read, so `dis` loaded through `importlib` and `inspect.signature` no longer raise a `TypeError` or `ValueError` CPython would not raise. A code object's `co_*` fields other than `co_name`, `co_flags` and `co_firstlineno` are refused in the program itself too, instead of raising `AttributeError`.
