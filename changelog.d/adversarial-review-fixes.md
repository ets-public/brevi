- **CPython conformance is in CI, as a ratchet.** `tools/conformance.py --check` now also fails when a known-wrong line is no longer wrong (the list in `compat/conformance_known_wrong.txt` only shrinks), when a built program crashes where it did not before (crashes are now in that list, next to wrong output and wrong exit codes), and when fewer tests match than `compat/conformance_floor.json` allows (the score only rises). It runs on every pull request that touches the compiler, on one toolchain, and in `tools/ci_local.sh` when `uv` is installed.
- **Architecture doc at v0.26.0** (`docs/ARCHITECTURE.md` now lists every file in `src/` and `src/dynpy`), and `bench/showcase/run.py` records the commit and the CPU in `results.json`.
- **The cost benchmark has a CPython-plus-hint control.** `bench/e2e.py --lang pyh` runs the Python prompt with the same native-code line the Brevi side gets, checked with CPython, so a heavy-task saving that comes from the line alone shows. Run twice per model on 9 November: with the same line on both sides, Brevi's side cost 0.46x of CPython's on Sonnet and 0.34x on Haiku, because the plain solution runs over the time limit on CPython and the model has to make it fast. The site's benchmarks page has the table next to the old uncontrolled 0.58x.
- **CPython conformance 58.2% -> 67.2%: 25 fewer wrong builds, 3 fewer crashes.** On CPython's own test_grammar, test_scope, test_int, test_list and test_dict, 209 of 311 tests now print exactly what CPython prints (was 181); 19 built programs still differ (was 44) and 2 still crash (was 5), all listed in `compat/conformance_known_wrong.txt`. Fixed in the dynamic build: an exhausted list iterator stays exhausted; `lst * huge` raises MemoryError instead of being killed; slice steps near `sys.maxsize` no longer overflow; `@=`, `/=`, `//=`, `%=`, `**=`, `^=`, `<<=`, `>>=` on objects call their in-place methods; `list.pop` rejects two arguments, `list.__init__` replaces the items, `list == list` checks the lengths again when an item's `__eq__` changes a list; `dict | dict`, `dict |= other`, `dict.update` raising when the other dict changes under it, `hasattr(dict, "__missing__")` is False; subclasses of `str`, `int` and `tuple` hash and compare by value, `super().__eq__`, `super().__hash__` and `super().__new__` work on them, `int(obj)` calls `__int__` and checks the result; a `__repr__` that is a staticmethod is called without self and `repr(lst)` reads the list as it changes; `int("10", 2, 1)` is a TypeError, `int("१२३")` reads Unicode digits in both builds; reading a local before its assignment in a function whose inner function captures it is an UnboundLocalError, not a NameError; functions have `__call__`; `sys.path` has the program's directory.
