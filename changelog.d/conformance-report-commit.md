- **Conformance reports name the commit they measured, and a release refuses reports from another tree.** v0.28.0's reports and release notes said "Brevi 0.27.1": main measured the v0.28.0 tree before the version bump, and its run after the release merge timed out, so the reports were never redone. Each report now gives the Brevi version and the commit it measured. `tools/release_notes.py --check`, which runs in release.yml's preflight (so in dry runs as well), fails unless both reports measured the version being released on the release's own tree. Main's conformance run gets 50 minutes instead of 30; its last three runs were cancelled at 30.
- **The conformance floors count native matches only.** The stdlib floor said 1990 while the report's coverage said 1988, because the floor counted the 2 tests that match only through the CPython bridge. Those do not count towards coverage, so a test moving from a native match to the bridge lowered coverage but still passed the floor. The floor now counts what coverage counts, and the stdlib floor reads 1988.
- README, the home page and `llms.txt` now show the current conformance numbers. They used to show v0.27's 80% core and 45% stdlib. The README also gives the tests refused by design (83 core, 6 stdlib), the shares of matches that print something to compare (88.2% and 94.3%) and the shares that take the typed fast path (2.6% and 1.2%).
