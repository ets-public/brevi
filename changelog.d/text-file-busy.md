- Fixed random "Text file busy (os error 26)" failures when many builds of the same program ran at once (32 parallel test jobs hit it). A build that took a program from the binary cache marked it as recently used by opening it for writing; cached programs are hard linked into place, so for that moment every other process starting a copy of it was refused by the kernel. The mark is now set through a read-only handle (Windows: attributes only), and it now also lands while the program is running, which the old write handle could not do. A build through cargo also writes a fresh output file instead of writing into one that may be linked to the cache.
