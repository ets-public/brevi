- Fixed a wrong answer in the typed build: an int passed to a parameter that other calls give a float (`def f(x): print(x)` with `f(2.5)` and `f(3)`, also `__init__` fields, methods and int defaults) printed as a float (`3.0`). Such a file now goes to the dynamic build, unless the parameter is only used where an int and a float give the same answer (next to a float, in `/`, compared, or formatted as a float).
- Fixed a wrong answer in the typed build: `sum()` of an empty list of floats printed `0.0` where Python prints `0`. `brevi run` now re-runs such a program on the dynamic build, and so does a float reaching a parameter the typed build holds as an int (it used to stop with "expected an int here").
