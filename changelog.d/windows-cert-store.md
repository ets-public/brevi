- Windows: HTTPS in Brevi's own requests and httpx now trusts the Windows certificate store when no CA file is given, read as CPython 3.13's `SSLContext.load_default_certs()` reads it: the "CA" and "ROOT" stores of the local machine, the current user, group policy, enterprise, services and users, keeping the certificates trusted for server authentication (an enhanced key usage that leaves server authentication out is not trusted). Certifi's bundle (or `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`) is still loaded beside it, so a root Windows has not downloaded yet still verifies. Before, a certificate trusted only through the Windows store, such as a company's own root, failed to verify. New parity checks in `tests/windows/parity.ps1` add self-signed certificates to the current user's "CA" store for one run, and verify a public site through the ROOT store alone, each compared with CPython's default context.
