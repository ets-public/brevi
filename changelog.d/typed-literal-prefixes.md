- Fix: a raw bytes literal (`rb"..."`, `br"..."`) in a `.py` file no longer builds typed as a `str` (it printed `a\x00` where Python prints `b'a\\x00'`). The typed build now refuses bytes literals, the `u`/`F`/`rf`/`fr` string prefixes and imaginary literals (`2j`) with a reason that names them, and the program builds over dynamic values, which reads all of them. Before, these fell back with a misleading parse error such as `expected ')', found "123\u0000"`, which looked like a NUL escape bug; `\0` escapes in `str` literals already worked.
