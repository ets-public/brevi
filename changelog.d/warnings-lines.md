- Dynamic build: a warning names the program's line, file and module as CPython's does. That covers `warnings.warn` in the program, a library's warning whose stacklevel points back into the program, and the warnings Brevi's runtime issues (re). It holds in functions, generators and coroutines across yields, lambdas, class bodies, functions a library calls back, and loop headers, so filters, the once-per-line `default` action and `showwarning` see what CPython sees (they saw `<sys>:0` before). A line the dynamic build cannot know is refused, never guessed: `warnings.warn(..., stacklevel=2)` in the program does not build, and a warning from a call that opens on a later line of its statement raises the dynamic build's "not supported" error. Only programs that import `warnings` keep lines.
A warning from a call that opens on a later line of a multi-line statement, whose line the dynamic build does not know, is raised when an "error" filter that names no line catches it (the line cannot change that answer) and refused otherwise.
`functools.partial` read from an instance (`class A: m = partial(f)`, then `A().m`) issues CPython 3.13's FutureWarning at that line. A program that uses `functools.partial` keeps line tracking on for this, the same cost as importing `warnings`.
