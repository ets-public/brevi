- Conformance fixes in the dynamic build, each matching CPython 3.13: `itertools.count(start=, step=)` takes its arguments by keyword (#477; before, a keyword step was silently ignored); codec names follow CPython's lookup and alias table for ascii, utf-8 and latin-1 (`ANSI_X3.4-1968`, `us`, `cp367`, `iso_8859_1:1987`, ...) in `bytes.decode`, `str.encode` and `open()` (#478); a program may assign `sys.stdout` (`sys.stdout = io.StringIO()`, `setattr(sys, "stdout", ...)`) and `print()` and `input()` write to it, with `sys.__stdout__` for the real stream (#479; assigning `sys.stderr` or `sys.stdin`, or `sys.stdout` in a program that runs a library in CPython, is refused); `print(file=obj)` calls `obj.write()` once per piece and `obj.flush()` for `flush=True`, as CPython does; `functools.lru_cache` hashes each call's key exactly once (#480); `operator.length_hint` is supported (refused for an iterator whose remaining count Brevi cannot show); `int(b"...", base)` works and a byte past 0x7f is never read as part of a number.
- Typed build: an undefined name inside `__del__` is no longer reported as a sure mistake (CPython ignores errors raised there), and `.dispatch()` / `.registry` of a `functools.singledispatch` function are known methods, so such programs build over dynamic values instead of being refused.
