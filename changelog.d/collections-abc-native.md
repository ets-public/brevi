- **`collections.abc` is native in the dynamic build**: the ABCs from CPython 3.13's `_collections_abc.py` with ABCMeta's rules (`isinstance`/`issubclass` through `__subclasshook__`, `register()`, the caches, `__abstractmethods__`, instantiation errors), subclassing with the mixin methods, `Mapping[str, int]` as a `types.GenericAlias`, and `type(Mapping)` being `abc.ABCMeta`. Before, a program using an ABC as a value ran CPython's ABCs through the bridge (about 27 ms to start; now about 4 ms). Builtin types answer the ABC hooks from an exact table of CPython's methods; an ABC check of a library type the table does not know is refused. `collections.abc.Callable[...]` is refused. Fixed with it: a class that defines `__eq__` without `__hash__` gets `__hash__ = None` (unhashable, and its subclasses too, as in CPython; before, it inherited a base class's `__hash__`); `object`'s `__eq__`/`__ne__`/`__lt__`/... read off an instance return CPython's answers (`NotImplemented` included); `type()` of dict views, `slice`, `...`, `NotImplemented`, builtin functions and bound methods names CPython's classes.
