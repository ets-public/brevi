- **Fixed: values shared through a library call stay shared (dynamic builds).** `pickle.loads(pickle.dumps([a, a]))` used to give back two separate lists, and a dict and the list it held came back unlinked. Every list, dict and set reached twice in one library call is now one object on the other side, in both directions, cycles included. That is what CPython does, and what pickle, copy and other libraries expect.
- **Fixed: `reversed(some_list)` is live (dynamic builds).** It used to iterate a copy, so a write made after `reversed()` was missed. It now reads the list as it goes and stops early if the list shrinks, like CPython's `list_reverseiterator`. Typed builds and dict views still iterate a copy (#459).
- **Fixed: list and dict iterators pickle as CPython's do.** An iterator and its list pickled together come back sharing the list, at the same position. A list's reverse iterator pickles as `reversed(list)` at its index, and a dict's reverse iterators pickle as their remaining items. The typed build gives a file that pickles an iterator to the dynamic build, which handles this. With these fixes the core conformance slice has no known wrong results and reads 91.7%, so the 90% release gate passes.
