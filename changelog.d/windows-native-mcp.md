- **Windows: native MCP servers over stdio and HTTP.** Brevi's own mcp copy now runs its server transports natively on Windows x64 instead of sending the program to CPython. A stdio server claims the process's stdin/stdout with `DuplicateHandle` for the protocol and moves the standard handles to NUL and stderr with `SetStdHandle` (as the SDK's `stdio_server` does on Unix with `dup`/`dup2`); `PeekNamedPipe` says when the pipe has bytes or is at EOF (a bare `WaitForMultipleObjects` signals an open pipe even with no bytes), with 1–10 ms sleeps so asyncio timers run while stdin is idle. A server over `run(transport="streamable-http")` or `"sse"` keeps its listening socket and accepted connections in tables of owned `TcpStream`s, and the event loop waits on them with `WSAPoll` (whose readable/writable bits are translated to the poll numbers the loop uses). Session ids come from `BCryptGenRandom`, and the sandbox's listen-host check is unchanged. A minimal stdio server answers `initialize`, `tools/list` and `tools/call` over pipes and exits 0 at EOF, including a tool that awaits a timer while stdin is idle; a streamable-HTTP server answers an `initialize` POST at `http://127.0.0.1:PORT/mcp` (SSE reply, `mcp-session-id`, 421/403 host checks, 413 body limit, DELETE), and the whole `tests/mcp_sdk` transcript suite, including the SSE transport, matches the CPython-generated `.expected` files on Windows.
