- **Release and install supply chain.** `install.sh` now takes everything from one release tag: it finds the latest release once (or uses `BREVI_VERSION`), and its source-build fallback builds that tag with `--locked` instead of `main` with fresh dependency versions. When `gh` is installed and signed in, it also checks the archive's build-provenance attestation and installs nothing if the check fails. The sandbox image and the dev container feature fetch `install.sh` and the SDK from the release they install, not from `main`. Both Docker images now run as an unprivileged `brevi` user and pin their base images by digest (checked in CI: the Rust image must really be the pinned Rust). The release workflow grants no permissions by default, and the MCP registry publisher it runs with an OIDC token is pinned by version and SHA-256.
