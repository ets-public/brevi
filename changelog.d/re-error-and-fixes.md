- **`re.error` / `re.PatternError` is a real exception in the dynamic build**, with CPython 3.13's exact messages and its `msg`, `pattern`, `pos`, `lineno` and `colno` (the regex parser was rewritten for it), and `re.error(msg, pattern, pos)` can be raised by programs. Checked with a differential fuzz against CPython (5,000 random patterns, valid and invalid). Written by DeepSeek, reviewed by Sonnet and Claude.
- **Fixed silent wrong answers in `re`** (dynamic build) that the fuzz found: `re.IGNORECASE` on non-ASCII letters now follows CPython (`K` and the Kelvin sign, `ß`/`ẞ`, `ı`/`İ`, `ſ`, `ς`/`σ`, `re.A|re.I` no longer folds `é`), scoped `(?s:.)`, `(?m:^)`/`(?m:$)` and `(?a:\b)` keep their own flags, `\B` never matches in an empty string, `lastindex`/`lastgroup` name the group that closed last, verbose mode skips only ASCII whitespace (so `re.escape` of `\x85` and `\xa0` matches, #419), variable-width look-behind raises CPython's error instead of being searched, `(?a)` with `re.U` raises `ValueError`, `\)` and `\>` do not end a `(?#...)` comment or a group name. Fixed-width look-behind now tries one start instead of every earlier position, and a `sub` template is parsed once per call.
- **`str.isidentifier()` uses CPython 3.13's identifier tables** in the dynamic build (it took any letter or number, so `'a²'.isidentifier()` was `True`), and `re` group names are checked with it.
