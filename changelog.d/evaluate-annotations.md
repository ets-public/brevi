- Dynamic build: module, class and def annotations are evaluated as CPython 3.13 evaluates them, so `x: undefined_name` raises NameError instead of passing silently; subscripts of classes and typing forms (`int[str]`, `Dict[str]`, `Callable[int]`, `Union[()]`, `G[int, str]` on a one-parameter Generic) raise CPython's TypeError, and those Brevi cannot check exactly stop as not supported.
- Typed build: a file where an annotation CPython evaluates could raise (`def f(a: Later)` above `class Later`, `o: Vec` inside class Vec's own body, a name bound on only some paths, `Callable[int]`, `"x" | int`) now goes to the dynamic build, which raises as CPython does, instead of printing a result CPython never reaches. The check is in src/ann_guard.rs, with CPython 3.13's subscript rules in src/pynames/ann_types.txt (tools/gen_ann_types.py).
- Brevi's pydantic: a model's annotations are evaluated through its field descriptors (as before), and an annotation outside a model that subscripts or combines a pydantic type or a descriptor alias stops as not supported rather than being evaluated on values that are not CPython's typing objects.
