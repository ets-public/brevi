- Security (v0.28.3): a sandboxed program can no longer plant code in Brevi's build cache for a later run to execute. `--allow-write` (and MCP `allow_write`) now refuses a folder that holds or lies inside the build cache, Brevi's temp folder or `BREVI_PY_CACHE`, since later runs replay binaries and link runtime libraries from there with no check. A cache folder another user owns or can write is no longer used (Brevi says so and uses a private one). The sandbox image no longer has a world-writable shared cache: each user has their own, and the runtime libraries come prebuilt from a read-only, root-owned seed (`BREVI_CACHE_SEED=/opt/brevi-seed`).
