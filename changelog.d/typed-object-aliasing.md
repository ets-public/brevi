- Security: the typed build no longer holds two writable references to one Python object (undefined behaviour in the generated Rust, found by Miri): object fields are borrowed one at a time. Programs where a call in the same statement could change a list the typed build is holding (`bx.rows[0].append(f(bx))`, `bx.items.append(f(bx))` with f rebinding `bx.items`, `f(bx.items, bx)`, also through a lambda) now go to the dynamic build; before they could crash or print a wrong answer. Programs that only read in such places (a module-level lambda, a module's attribute passed on, a method of an imported module) keep the typed build. The runtime allocator's pointer handling is also fixed so Miri finds no undefined behaviour in it.
