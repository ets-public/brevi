- **`__del__` works in dynamic builds.** A class's `__del__` runs when the last reference to an instance goes, as in CPython: on rebinding or `del`, when a list or dict is cleared, when a loop variable moves on, when a function returns, and at exit (globals finalized while every global can still be read). Tuples and `list.clear()` free their items last first, as CPython does. An exception in `__del__` prints "Exception ignored in" on stderr and the program goes on. A `__del__` or `__eq__` that clears a dict during `==` between dicts no longer crashes. Before, the dynamic build refused any class with `__del__`. Known gaps: the order objects are finalized in at exit, and when a list is freed whole, can differ from CPython's (CPython does not promise it either); reference cycles are not collected. 7 more CPython `test_dict` and `test_scope` tests build and match.
- **CPython conformance 74.0% -> 77.5%** (241 of 311 on both builds; 44 refused, 9 wrong, 2 crashes), with `__del__` above and the DeepSeek fixes merged before this. `compat/conformance_floor.json` is raised to 241 and 241.
