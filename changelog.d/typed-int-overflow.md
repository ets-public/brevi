- Python ints on the typed build are never wrapped or capped. `int(1e20)` printed 9223372036854775807 and `int(-1e30)` printed None; a program whose int outgrows 64 bits (a factorial, `int()` of a big float, a big power used in a list) stopped with "attempt to multiply with overflow". Now `brevi run` (and the MCP `run` tool without cases) runs such a program again from the start on the dynamic build, whose ints have no limit: it gets the same stdin, only output the first run had not written yet is passed on, and that run must write the same output first or it is stopped with an error. A program that writes files, reaches the network or runs native code is not run twice: it stops with an error that says so, as does a binary from `brevi build` run by itself (build with BREVI_DYN=1 for big ints there).
- `(h * 1000003 + ord(c)) % MOD` and other int sums of products taken `%` a number are worked out in 128 bits, so a rolling hash modulo 2**61 - 1 stays on the typed build and gives Python's answer.
- `round(x, n)` matches CPython for floats with negative n (`round(1234.5678, -2)` is 1200.0, was 1235.0) and n over 15 (`round(1e-20, 20)` was 0.0), and for Fractions with negative n; `round(Decimal, n)` outside 0..9 runs on the dynamic build.
- `x << n` no longer drops bits past 64 on the typed build (`(1 << 62) << 2` was 0), and `x >> n` past 63 is 0 or -1 as in Python instead of an error.
