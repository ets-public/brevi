- Dynamic builds: a program module's repr is CPython's (`<module 'helper' from '/abs/helper.py'>`), and its `__file__`, `__name__`, `__doc__` and `__package__` read as CPython's, where they raised AttributeError before; a module's own `__doc__` and `__package__` names work too. Its `__spec__`, `__loader__`, `__cached__`, `__dict__`, `__builtins__` and a package's `__path__` are refused. A library module's repr, which printed `<module 'math'>`, is now refused when the build sees it (`print(math)`, `f"{math}"`) and stops the program otherwise (except `sys` and `builtins`), as are the reprs of `sys.stdout` and `decimal.getcontext()`. On Windows `__file__` no longer starts with `\\?\`.
