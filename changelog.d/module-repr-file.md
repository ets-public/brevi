- Dynamic builds: a program module's repr is CPython's (`<module 'helper' from '/abs/helper.py'>`), and its `__file__`, `__name__`, `__doc__` and `__package__` read as CPython's, where they raised AttributeError before; a module's own `__doc__` and `__package__` names work too. Its `__spec__`, `__loader__`, `__cached__`, `__dict__`, `__builtins__` and a package's `__path__` are refused. A library module's repr, which printed `<module 'math'>`, is now the one the build machine's CPython prints (`<module 'math' (built-in)>`, `<module 'json' from '...'>`). The reprs of `sys.stdout` and `decimal.getcontext()` are refused when the build sees them and stop the program otherwise. On Windows `__file__` no longer starts with `\\?\`.
