- The typed build's `re.IGNORECASE` (`re.I`, a leading `(?i)`) now matches as CPython 3.13's `re` does. Before, it lowercased the text and the pattern with rustc's Unicode tables, which gave wrong answers: `ſ` did not match `s`, `İ` matched nothing, `\x41` did not match `a`, and `re.I | re.A` still folded non-ASCII characters (the Kelvin sign matched `k`). It now compiles each character and set as CPython does, with `_sre`'s case tables and `re._casefix`'s extra cases (generated into `src/unicode_sre.rs` by `tools/gen_unicode.py --sre`, shared with the dynamic build), and folds only ASCII letters under `re.ASCII`. It is also faster: the text is no longer lowercased again for every search position.
